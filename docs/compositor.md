# 独立画布合成

## 范围

画布固定为 1920×1080、RGBA8，后台以 30 Hz 目标节奏合成图片、显示器和摄像头来源，保留原有来源顺序、显隐、变换、透明度和来源滤镜。预览显示完成的合成纹理，再在窗口上绘制选框、缩放及旋转手柄；编辑辅助内容不进入输出画布。

本阶段提供独立合成及共享 GPU 帧接口，不包含音频、编码、MP4、录制控制或设置界面。

## 职责与线程

- `CanvasRenderer` 只读取来源快照，负责纹理上传、D3D11/OpenGL 互操作、来源滤镜和画布合成。不访问窗口或来源模型。初始化、绘制及所有 GL 资源销毁均要求所属上下文处于 current 状态。
- `Compositor` 提供启停、来源快照和最新合成帧接口，可以脱离预览控件单独运行。控制端在 GUI 线程创建共享上下文和 `QOffscreenSurface`，随后将上下文移交后台线程；后台线程负责 GL 工作及资源清理，表面在工作线程结束后由 GUI 线程销毁。创建共享上下文放在 GUI 线程，以兼容 WGL 对正在其他线程使用的共享上下文的限制。
- `PreviewWidget` 保留鼠标交互、命中测试、选框和等比显示。GUI 定时查看最新输出，只在出现新帧时请求刷新，不为每个后台帧投递事件。
- 当前集成由 `PreviewWidget` 管理合成器生命周期，首次初始化预览时启动；隐藏、最小化不停止。预览上下文重建时停止并重建共享合成上下文，保留来源快照和编辑状态。后续接入录制控制时，需要明确其对输出生命周期的持有关系，不能把上下文重建误认为一次录制启停。

三个来源控制器分别发布图片、显示器和摄像头的完整快照，不相互汇总其他类型的来源。`VideoSourceAggregator` 在 GUI 线程保存各类型的最新快照，按照 `VideoSourceModel` 的层级顺序和可见性、锁定、变换及滤镜状态生成完整列表，再通过 `PreviewWidget` 提交合成器。同一轮事件中的多次更新合并为一次排队发布；删除的来源不会因迟到的快照重新进入输出。

采集控制器仍在 GUI 线程取各采集后端的最新帧；GUI 暂停处理事件时，合成线程能持续输出已收到的画面，但不会因此获得尚未由控制器和汇总器提交的新采集帧。

## 有界交接及同步

- 输入仅保存一个最新来源快照，后续修改覆盖之前的快照，不累积待渲染任务。渲染期间使用本次快照副本；模型和 GUI 对象不跨线程访问。
- 输出使用三个共享纹理槽。`CompositionFrame` 是不可变帧租约，包含纹理 ID、尺寸、输出序号、来源快照修订号、合成单调时间，以及已上传来源的帧标识。
- `latestFrame()` 返回最新租约。消费者持有租约期间，该槽不会被生产者覆盖；全部槽都被占用时跳过本次输出发布，不增加缓冲。消费者必须使用共享组内的上下文，完成 GPU 读取后才能释放租约，并在调用 `stopRendering()` 前释放所有租约。停止或致命错误清理后纹理 ID 不再可用。
- 首版用生产者和预览端的 `glFinish()` 保证跨上下文写入、读取完成，优先保证正确性。该同步可能等待 GPU，后续可依据性能数据改成 fence；本阶段不宣称零等待或零拷贝编码。
- 正常输出按单调时钟调度，错过截止时间后跳过错过的节拍，不突发补画。序号表示已发布帧数；时间戳表示合成时间，不是来源捕获时间，也不是录制 PTS。后续音画同步仍需独立设计录制时间线。
- `captureImage()` 是阻塞式诊断读回接口：由后台线程合成并读取不早于调用时来源快照的画布，最多等待指定超时。仅供截图及测试，预览热路径不调用；诊断请求可以提前触发合成，不应将诊断期间发布序号当作准确的 30 FPS 采样计数。

删除来源、清空画面或切换采集代次后，后台下一次合成负责释放过期上传资源和互操作导入；不需要让已隐藏的预览执行 `paintGL()`。停止时唤醒线程，等待工作线程完成上下文内的资源清理，不等待 GUI 回调。

## 验证

```powershell
ctest --test-dir build/recording-compositor-Debug --output-on-failure
```

- `gpu.compositor`：固定画布、FBO 绑定保护、滤镜中间结果透明度、纹理复用及释放、无 GUI 事件时后台持续输出、停止重启、三纹理租约不可覆盖和有界背压。
- `ui.previewwidget`：隐藏及最小化后持续合成、后台应用来源及滤镜修改、恢复窗口后显示最新画面，以及原有缩放、方向、叠加、旋转、选框隔离、鼠标交互和上下文重建回归。
- `capture.interop`：真实 WGC 和 GPU 互操作；最小化时合成序号继续增长，来源删除后后台清理导入，不积压旧帧。异步合成后的像素断言先等待诊断读回。
- `ui.mainwindow` 的原生预览测试适配异步合成；可通过 `OPENLIVE_CAMERA_HARDWARE=1` 单独运行 `cameraHardwarePreview`，检查真实摄像头、滤镜、编辑及最小化时输入修订号与输出序号持续增长。

GPU 测试需要原生 Windows 桌面及桌面 OpenGL。检查 QtTest 明细中的 skipped 数，不能只凭 CTest 返回成功就认定实际执行了 GPU 验收。沙箱可能使真实 WGC 不可用，需要在允许访问交互桌面的环境运行。

2026-10-28 本机验收（NVIDIA GeForce RTX 4060 Ti，125% 缩放）：

- Debug 应用与测试构建成功，8 组 CTest 全部通过。
- 合成器测试 6 项、预览测试 26 项、屏幕采集及互操作测试 10 项通过，三组均无跳过。
- 单独开启摄像头硬件验收，原生主窗口启停、图片叠加与显隐/排序、鼠标编辑、真实摄像头灰度滤镜及最小化持续更新通过，6 项（含测试初始化和清理）均通过且无跳过。
- 这些结果覆盖本阶段的功能回归，不替代后续录制性能、音画同步或长时间稳定性验收。
