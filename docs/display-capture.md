# 显示器采集

首版支持 Windows 10 22H2、Windows 11 的 SDR 显示器采集。窗口、摄像头和 HDR 色调映射不在本阶段实现范围。

## 线程与帧所有权

- 每来源一个 `DisplayCaptureWorker`，在后台初始化 MTA、WGC 和 D3D11；同一显示器的多个来源独立启停。
- WGC 帧池容量为 2；采集线程定时清取，只处理最新帧。30 FPS 是应用处理和发布上限，不约束系统内部产帧。
- `LatestCaptureFrame` 只保留一张待交接帧。互斥锁仅交换所有权，复制、GPU 等待和旧帧销毁均在锁外。
- GUI 定时取最新帧，不向 Qt 事件队列逐帧投递画面。模型只保存来源配置、尺寸和状态，不保存视频帧。
- 帧携带尺寸、单调时间戳、序号和会话代次。隐藏、切屏、重试会停止旧会话，旧代次的结果不会重新进入画布。

## GPU 与 CPU 路线

WGC 帧先复制到应用持有的 D3D11 纹理，后台查询确认 GPU 复制完成后再发布。固定三个纹理槽位通过帧的租约标记占用；没有空闲槽位时丢帧，不扩容，也不覆写仍被消费的资源。

预览在当前 OpenGL 上下文中检查并尝试 `WGL_NV_DX_interop2`。注册、锁定后，将 D3D11 纹理在 GPU 内复制到预览自己的 GL 纹理，再解锁。后续来源变换、滤镜及画布合成共用原有链路，不依赖 WGC 帧池资源的寿命。这条路线避免 CPU 像素读回，但包含 GPU 内部复制。

互操作失败时，该会话改用后台 staging texture 读回，按 RowPitch 深拷贝成 `QImage`，仍使用同一个交接槽。GUI 复用同尺寸的 GL 纹理存储上传像素。会话内不反复升级；手动重试或重新打开会话可重新尝试 GPU。

采集失败、显示器断开属于来源错误，不触发传帧降级。来源保留，清空画面，由用户手动重试；不自动改采其他屏幕。

## 停止与释放

隐藏暂停采集，恢复后等待新帧。窗口最小化不停止采集。删除立即移除模型和预览帧；后台线程异步关闭 WGC、撤销事件并释放 D3D 资源。预览即使不可见，也会在正确上下文中解除过期的 GL 互操作注册。正常删除不在 GUI 线程 join；应用退出时统一等待尚未结束的线程。

工作线程在 COM 卸载前清理 C++/WinRT 工厂缓存，避免最后一个 MTA 退出后留下失效的缓存指针。

## 验证

`tst_captureinterop` 覆盖交接槽、已知颜色的共享纹理、GPU/CPU 输出一致性、来源失败、重复来源、显隐、属性修改、回退和资源释放。硬件测试需要交互式 Windows 桌面；无相应能力的环境明确跳过硬件项。

可设置以下环境变量后运行测试：

- `OPENLIVE_REQUIRE_GPU_INTEROP=1`：硬件验证不允许因缺少互操作能力而跳过。
- `OPENLIVE_CAPTURE_SOAK_SECONDS=600`、`QTEST_FUNCTION_TIMEOUT=900000`：运行 `controllerLifecycleAndGpuPreview` 的十分钟动态画面测试，记录帧数、GUI 调度间隔、私有内存和句柄数。
- `OPENLIVE_FORCE_CPU_CAPTURE=1`：强制从 CPU 路线启动。
- `OPENLIVE_FORCE_INTEROP_FAILURE=1`：注入互操作失败，验证自动回退。仅用于诊断，不是产品设置。

跨显卡和不同厂商驱动必须分别实测。系统允许 WGC 不代表当前 D3D11 与 OpenGL 设备一定能够互操作，CPU 回退是正式支持的路径。

## 本机验证记录

2026-10-28，RTX 4060 Ti、2560×1440 显示器：十分钟 GPU 动态采集观察到 16,829 次新帧更新（约 28 FPS），GUI 检查循环最大间隔 68 ms；私有内存基线/末次采样为 322,527,232 / 321,024,000 字节，句柄数为 586 / 580。无意外降级，结束后的强制 CPU 回退、显隐与释放检查通过。

严格桌面硬件测试 10 项、原有预览 GPU 回归 20 项均通过且无跳过。普通 CTest 的六组测试通过；受限桌面中的真实采集项会跳过，必须另跑严格硬件测试。上述记录不代表其他 GPU、混合显卡或 HDR 环境已验证。
