# 摄像头采集

## 范围与后端

Windows 摄像头视频使用原生 Media Foundation 的异步 Source Reader；不通过 FFmpeg DirectShow，也不启动外部进程。屏幕继续使用 WGC。摄像头可接入 MF 能枚举、打开并转换为 RGB32 的物理和虚拟设备；旧式 DirectShow 专用虚拟摄像头不在首版支持范围。

本次没有音频、镜像、曝光/对焦/白平衡、厂商控制面板或来源配置持久化。后续摄像头麦克风应作为独立音频来源管理，画面显隐不控制麦克风。

## 线程与帧交接

- 设备枚举、模式查询在后台查询线程执行，COM/MF 在各自线程初始化和清理；不在 GUI 线程激活设备。
- 每来源一个后台工作线程，Source Reader 回调只保留最新 `IMFSample`，工作线程复制最新 RGB32 图像，另一交接槽只保留最新 `CameraFrame`。只维持一个后续读取请求，不逐帧投递 GUI 事件。
- MF 负责 MJPEG 等输入的系统解码及受支持格式到 RGB32 的转换。CPU 帧上传 OpenGL 后，共用现有变换、滤镜与画布合成。支持正负 stride 和行对齐；帧不依赖采集缓冲的寿命。
- 每帧带会话代次、序号、MF 设备时间戳和回调收到帧时的单调时间戳。后者尚未校正设备延迟，不构成音画同步实现。
- 停止先与后续 `ReadSample` 提交互斥，再异步 `Flush`，在后台等待 `OnFlush` 与在途采样回调清退，最后释放 reader/source 和 COM/MF。
- GUI 定时取最新帧，按模型顺序合并图片、屏幕和摄像头。像素不进入来源模型；同设备的旧会话结束后才允许重开，其他设备不必等待。

正常隐藏、删除、配置切换均不在 GUI 线程 join。应用退出等待后台线程；异常驱动若阻塞设备激活、停止或不完成 Flush，进程内后端无法保证硬性退出上限。本次未引入采集进程隔离。

## 设备、模式与属性

- 用 MF symbolic link 标识设备，不依赖显示名称或枚举顺序。同一设备禁止重复添加，不同设备可以同时采集；同名设备应以 ID 区分。设备换 USB 接口或重装驱动后 ID 可能改变，不按名称猜测替换。
- 打开添加/属性窗口和点击刷新时重新枚举设备。模式查询缓存避免对正在采集的设备重复打开；刷新时清理非活动设备缓存。设备断开仍保留原选择。
- 默认选项为“设备默认”。显式模式来自设备的原生媒体类型，支持有理数帧率；界面选择尺寸和帧率，内部尝试对应的可转换原生格式，不组合未声明的尺寸/FPS。
- 打开后检查实际输出尺寸与帧率。帧率允许 `max(0.001 FPS, 请求值 × 0.0001)` 的量化容差，超出则报错，不静默降规格。属性显示的是协商帧率，不是测得的持续出帧率。
- 属性窗口编辑草稿，确定后应用，取消不改当前配置。应用失败保留新配置、清空画面并显错；重试使用已应用配置。
- 换设备或输入尺寸改变后，保留画布中心、显示宽度与旋转，高度按新宽高比调整，保留显隐、锁定和滤镜。系统更新输入尺寸不受用户拖动锁定限制。

## 故障与释放

隐藏正常来源释放设备，恢复可见时重开。采集故障保留具体错误并要求手动重试；显隐切换不会清除故障并隐式重试。删除立即清除预览，后台释放资源。

启动后等首帧 10 秒、运行中无有效帧 5 秒后失败；低帧率模式至少等待三个帧周期。时间从成功提交读取后开始计算，不能中断阻塞的驱动打开调用。静止画面持续产生帧时不算断流。模式改变、设备读错、流结束也会停止该来源并清空旧画面，不影响其他来源。无法从 HRESULT 确定原因时，错误提示列出检查方向并保留错误码，不武断声称设备被占用。

## 验证

普通 `ctest --test-dir build/camera-capture-Debug --output-on-failure` 包含 `capture.camera`，覆盖配置、分数帧率、重复设备、锁定时尺寸适配、滤镜保留、无效设备错误、故障显隐、手动重试、删除及图片合并；UI 测试覆盖固定浅色配色、属性草稿取消/确定、窗口复用和来源删除关闭窗口。普通测试不要求打开摄像头。

手动运行硬件验收时设置：

```powershell
$env:OPENLIVE_CAMERA_HARDWARE = '1'
$env:OPENLIVE_CAMERA_STRESS_MS = '60000'
# 在 Qt DLL 已加入 PATH 的环境中执行：
& ./build/camera-capture-Debug/tst_cameracapture.exe hardware -o camera-results.txt,txt
& ./build/camera-capture-Debug/tst_mainwindow.exe cameraHardwarePreview -o camera-preview-results.txt,txt
```

`hardware` 必须对所有 MF 枚举设备成功采集，检查显隐释放/重开、显式模式、无效模式失败后恢复、删除释放，并记录持续帧更新、内存及句柄。两台以上 MF 设备时同时启动，不能因设备失败而跳过成功要求。`cameraHardwarePreview` 需交互式 Windows 桌面，验证真实采集、OpenGL 上传、灰度滤镜、窗口缩放和隐藏释放。

2026-10-28 本机验证：

- Debug 构建成功，7 组 CTest 全部通过；硬件项在普通运行中明确跳过。

- 持续 60 秒观察到 1,494 次更新（约 24.9 次/秒，不能等同于协商帧率），最大更新间隔 80 ms。私有内存基线/末次为 20,652,032 / 20,537,344 字节，句柄为 535 / 538。
- 显隐释放/恢复、显式模式切换、不支持模式保留配置并报错、修改后恢复及删除释放通过。
- 原生桌面 OpenGL 实机预览、灰度滤镜、窗口缩放，以及深浅主题属性窗口验证通过。

- MF 虚拟设备、双设备并行、物理拔插、其他厂商驱动和长时间运行仍待对应实机验证；本次一分钟记录不替代长期稳定性验收。
