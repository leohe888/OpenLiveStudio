# MP4 录制链路

## 输出与时间线

`RecordingController` 提供开始、停止、状态、时长、输出文件和错误接口；`RecordingWorker` 在后台调用 FFmpeg 库完成编码和封装，不启动 FFmpeg 子进程。画布输出固定 1920×1080、30 FPS、H.264/libx264、YUV420P、BT.709 limited；三个质量档使用 CRF 23/20/17，速度为 veryfast。音频固定 AAC、48 kHz、双声道、192 kbps。

- 合成和混音共用 `MediaClock`（Windows QPC 纳秒）。初始化编码器、文件和首幅画布后建立本次录制起点；视频使用 `n/30`，音频使用采样数/48000 分配 PTS。
- 合成线程在输出开启时才进行持续 CPU 读回，最多保留 8 幅图像。时间戳取读取来源快照的时刻，不包含后续 GPU 渲染与读回耗时；录制线程选择距离目标时间最近的快照，避免两个 30 Hz 时钟相位差额外延迟一帧。来源未更新或短暂上下文重建时重复上一幅画面，不把编辑选框写入文件。
- 混音本身有 60 ms 抖动缓冲；录制延后约 200 ms 处理各时间点，使画布和对应时刻的音频都能到达。该处理延迟不改变文件中的音画时间关系。
- 每帧视频对应 1600 个音频采样，缺失区间补零；无声音来源时仍生成静音音轨。`missingAudioSamples` 统计混音输出本身的缺包，不把来源本来无声计为缺包。
- 编码队列有上限，音频输出溢出、编码持续落后一秒或合成长期停止时结束录制并报错。停止后排空编码器并写 MP4 trailer；失败时尝试完成已有内容的封装，保留错误和文件完成标志。

Qt 文件 I/O 负责 Unicode 文件名和写盘，采用 NewOnly 创建文件，永不覆盖现有文件。未写入视频的失败/取消尝试会清除本次新建的空文件；真实录制失败后的内容保留。正常 MP4 仅保证正常完成后的可播放、可定位，不提供崩溃恢复。

## 生命周期

初始化成功才进入 recording。停止录制仅关闭本次输出接口，不停止来源采集、混音或预览。控制器销毁会请求停止并等待后台封装完成，必须早于合成器和混音器销毁。预览上下文重建有 500 ms 恢复窗口，期间重复旧画面，超时则报错。

阶段 C 提供录制服务及测试接口；阶段 D 已接入控制按钮、统一设置和关闭窗口等待行为。阶段 E 已完成本机十分钟录制、编码后同步信号对照和动态编辑综合验收，复现方式、测量结果及覆盖边界见[录制综合验收](recording-acceptance.md)。

## 设置与窗口行为

“设置”打开单实例对话框，分为“直播推流”和“录屏”。录屏保存目录默认为系统视频目录下的 `OpenLiveStudio`，质量默认为高质量；目录在开始录制时按需创建，文件名使用本地时间并在重名时追加序号。录屏固定 MP4、1080p、30 FPS。

直播页可编辑 RTMP/RTMPS 地址和默认遮蔽的串流密钥，直播按钮仍禁用。所有输出设置只在当前运行期间有效，不写入配置文件、注册表或凭据管理器；取消不应用草稿，重新运行恢复默认值。

录制从启动到封装结束期间，目录和质量均锁定，声音与画面来源仍可修改。录制按钮显示启动、录制、停止状态；底部显示时长，错误通过状态栏及提示文本显示，明确区分已有内容是否完成封装。关闭窗口会请求停止，保持事件处理直到后台完成封装，再关闭窗口；销毁顺序保证编码线程先于合成器和混音器退出。

## 基础验证

`output.recording` 使用真实离屏 GPU 合成和 FFmpeg 编码，并通过独立 ffprobe 检查 H.264/AAC 轨道、分辨率、30 FPS、起始时间、音视频时长差、Unicode 文件名和已有文件不被覆盖。另覆盖静音录制、来源变更、重复启停、初始化失败、启动中取消和停止后继续合成/混音。

普通 `ctest --test-dir build/recording-compositor-Debug --output-on-failure` 包含该测试；需要桌面 OpenGL 和 FFmpeg 开发包中的 ffprobe。基础短录制不替代十分钟同步和稳定性验收。

`outputSettingsDialogDraftsAndTheme` 验证草稿取消、输入校验、密钥遮蔽、深浅主题和临时设置；原生桌面的 `recordingControlsAndGracefulClose` 验证真实录制按钮、配置锁定、最小化持续录制和关闭等待。
