# Linux 移植规格

日期：2026-11-04。状态：范围已确认，待实施；真实图形验收环境待补充。

本文描述 Linux 专用版本的目标行为，不代表当前代码已经实现。当前任务只编写规格，不安装依赖、不修改功能、不提交或推送。

## 1. 目标与范围

在新分支 `codex/linux-port` 上将 OpenLive Studio 移植为 Linux 专用桌面程序。允许删除 Windows 专用采集实现、GPU 互操作、构建配置和测试；保留仍被使用的跨平台业务逻辑。该分支不承担 Windows 兼容性维护。

首版完成以下闭环：

```text
显示器 / 摄像头 / 图片 → 来源管理 → OpenGL 合成 → 预览 ┐
麦克风 / 系统声音 → 重采样 → 混音 ───────────────────┤
                                                   ↓
                                      时间线 → FFmpeg 编码
                                                   ↓
                                          MP4 录制 / RTMP 推流
```

必须支持录制和推流同时运行，停止其中一个不得中断另一个。首版目标为 1920×1080、30 fps 输出，允许使用软件编解码。

继续提供现有来源的显隐、排序、位置、缩放、锁定、滤镜及音频音量、静音控制。

## 2. 开发与运行环境

允许在 Ubuntu 虚拟机内使用 Codex CLI 开发、构建和运行测试。真实设备与交互测试需要图形桌面、可用的 OpenGL、音频服务和可访问的摄像头。

已检查的开发主机为 Ubuntu 22.04.5 LTS，当前会话为 tty，没有 DISPLAY 或 WAYLAND_DISPLAY；尚未发现 CMake、pkg-config、Qt 6、FFmpeg 及采集后端的系统开发包。此结果不排除非系统路径中的自定义依赖。

实施前需要明确并记录：

- 图形验收机器的发行版版本、桌面环境、Wayland 或 X11 会话类型。
- Qt、FFmpeg、PipeWire、Portal 实现和音频服务版本，以及 GPU/驱动、摄像头型号。
- 虚拟机的虚拟化平台、图形加速、音频配置和摄像头直通情况。

首版只对指定的一个图形环境承诺验收，不以一次测试声明覆盖所有发行版或两种会话。虚拟机采集的是虚拟机内部桌面和音频；宿主机内容不在默认范围内。最终性能与设备恢复还应在实际目标 Linux 机器上复核。

Qt 维持项目当前的 6.5+ 要求，不假定 Ubuntu 22.04 的默认软件源能满足。依赖安装方式需在构建阶段确定并写入 README。

## 3. 后端选择

| 功能 | 首版后端 | 说明 |
| --- | --- | --- |
| 显示器采集 | XDG Desktop Portal ScreenCast + PipeWire | Portal 请求用户选择和授权，PipeWire 接收视频帧 |
| 摄像头 | V4L2 + FFmpeg libavcodec | V4L2 采集原始或压缩数据，压缩数据软件解码 |
| 麦克风 | PulseAudio API（libpulse） | 采集音频输入 source |
| 系统声音 | PulseAudio API（libpulse） | 采集所选播放设备 sink 对应的 monitor source |
| 图片 | Qt QImageReader | 保留异步加载与 QImage 路径 |
| 合成与预览 | Qt + OpenGL | 复用现有渲染器和像素着色器 |
| 编码与封装 | FFmpeg | 复用现有录制和推流输出路径 |

音频后端既可连接 PulseAudio，也可连接 PipeWire 的 `pipewire-pulse` 兼容服务。原生 PipeWire 音频 API 和 ALSA 不属于首版范围。PipeWire 视频采集与 PulseAudio 音频采集是不同职责，不应因使用同一桌面音频服务而混为一个后端。

## 4. 显示器采集

添加来源时通过 Portal 请求会话、选择来源并启动流，使用其返回的 PipeWire 连接和节点接收帧。接受系统提供的屏幕选择与授权界面，不复刻 Windows 的显示器枚举和句柄绑定方式。

首版验收显示器采集。系统选择器如果提供窗口选项，可保留该选项，但不额外承诺窗口采集的专项兼容与验收。

首版优先协商可通过 CPU 访问、且现有渲染器支持的像素格式，按实际 stride 和缓冲边界封装为 `CaptureFrame::pixels`。不要求先完成 DMA-BUF 到 OpenGL 的导入；协商不到可用格式时应明确报错。

处理分辨率、像素格式变化和来源关闭；取消系统选择不得留下无效来源或悬挂的采集线程。Portal 会话失效后显示异常，提供重新选择和授权的入口，不无限触发系统授权弹窗。

## 5. 摄像头采集

使用 V4L2 查询能力、格式、分辨率和帧率，并持续采集。设备路径不作为唯一长期身份，重连时不得仅凭 `/dev/videoN` 相同就绑定另一台设备；无法唯一识别时由用户重新选择。

保留现有设备、格式、分辨率和帧率联动选择。显式模式不支持时报告错误，不静默换成其他模式。

首版支持能够映射到现有 PixelFrame 的常用 8 位未压缩格式，以及设备实际提供的 MJPEG/H.264 软件解码。复用现有颜色范围、矩阵处理和不支持格式的错误提示；不声明所有摄像头都具备这些模式。

原始帧直接进入像素帧路径；压缩数据保持解码依赖关系，只在完整解码后保留最新画面。处理实际行步长、平面布局、缓冲归还和停止时的阻塞解除。恢复 H.264 解码需重新建立解码上下文并等待可解码的关键帧。

设备断开时显示异常并尝试有间隔的重连，不忙轮询。用户删除来源或主动停止后取消重连。

## 6. 音频采集

麦克风枚举非 monitor 的输入 source；系统声音展示播放设备，并绑定其 monitor source。系统声音指所选播放设备上的混合声音，不承诺跨所有输出设备汇总，也不包含按应用采集。

采集数据附带时间信息，经现有重采样路径统一为 48 kHz、双声道交错 float，再进入 AudioMixer。不得把音频服务的时间戳直接当作项目单调时钟，需建立并验证时间映射。

区分默认设备选择与显式设备选择：默认选择跟随服务的默认设备变化；显式选择在设备消失后等待原设备恢复，不静默切换到其他设备。

音频服务断开后清理旧连接、流和过期数据，尝试重连并重新枚举；缺失音频由时间线补静音。设备恢复后重新对齐时间，避免积压数据造成延迟或音画跳变。

## 7. 共用架构与资源生命周期

保留来源管理器、控制器、渲染快照聚合、合成器、混音器、独立输出订阅、时间线与编码器的职责边界。平台采集 API 封装在采集层，不进入 UI 和输出层。

首版视频数据路径以 CPU 像素帧上传 OpenGL 为主。删除 Windows GPU 实现时检查所有调用者，清理失效的 D3D11 字段和互操作分支，不保留误导性的硬解状态提示。

队列与缓冲必须有界。预览可取最新完整帧；录制与推流各自消费输出订阅，不能争抢队列。继续使用统一单调时钟，保留缺帧复用和缺音频补静音策略。

停止、删除来源、退出程序时，必须解除采集等待并释放 Portal 会话、PipeWire 流、V4L2 缓冲与设备、PulseAudio 流和线程。禁止在资源仍被渲染使用时提前释放。

## 8. 故障行为

来源采集失败不主动停止整个录制或推流，界面应展示异常原因。暂时缺失视频沿用既有最后有效画面策略，暂时缺失音频补静音；恢复后消费新数据。

摄像头、音频设备和音频服务尝试重连；屏幕会话失效需要用户重新授权。删除来源后其最后画面必须移除，不得继续保留为幽灵来源。

输出自身失败仍按录制或推流控制器的策略处理。磁盘写入失败、编码错误和推流网络故障不属于来源恢复逻辑；一个输出失败不应直接停止另一个健康输出。

## 9. 实施阶段

1. **构建基础**：创建 Linux 分支，配置 Qt/FFmpeg 等依赖，清理 Windows 构建项；跑通窗口、图片合成、软件编码与文件录制。
2. **音频闭环**：实现 libpulse 枚举、输入和 monitor 采集、时间对齐及服务重连，验证混音录制。
3. **摄像头闭环**：实现 V4L2 模式选择、原始帧与压缩帧采集、软件解码及断开恢复。
4. **屏幕闭环**：实现 Portal 交互、PipeWire 视频帧接入、格式变化和重新授权。
5. **集成验收**：多来源同时工作，验证 MP4、RTMP、独立启停、设备恢复和资源清理，更新运行与测试文档。

每阶段只删除已被替代的 Windows 实现；最终分支不依赖 Windows SDK。实现后保留工作区改动，不自动暂存、提交或推送。

## 10. 验收标准

| 项目 | 通过条件 |
| --- | --- |
| 构建 | 指定环境可按文档从干净构建目录配置和编译，不依赖 Windows SDK 或个人绝对路径 |
| 基础界面 | 正常启动、预览、添加/删除来源、变换、层级、滤镜与音量控制 |
| 显示器 | 系统选择与授权后有画面；取消、重复启停、尺寸变化和会话关闭行为正确 |
| 摄像头 | 实际设备可枚举、选择有效模式并预览；无效显式模式报错；原始/压缩模式按设备能力分别记录结果 |
| 音频 | 麦克风和所选播放设备声音可分别采集、静音、调音量并混合；切换默认设备与显式设备的行为符合规格 |
| 输出 | 一路显示器、一路摄像头、图片、麦克风和系统声音同时参与，输出 1080p30 MP4 与 RTMP |
| 独立启停 | 同时输出时停止录制不影响推流，停止推流不影响录制；分别重新启动仍可工作 |
| 来源故障 | 拔插摄像头/麦克风、重启音频服务、关闭屏幕会话时输出继续；恢复或重新授权后正常工作 |
| 生命周期 | 重复添加、删除和启停不崩溃、不遗留采集线程；运行时记录内存、句柄/文件描述符变化 |
| 媒体有效性 | ffprobe 检查流信息、时长和时间戳，实际播放/接收检查声音、图像与同步；不能仅以成功生成文件判定通过 |

基础集成连续运行至少 30 分钟，包含同时录制和推流。使用可观察的同步事件测量开始和结束处的音画偏差，记录偏差与漂移；最终可接受偏差阈值及性能参考硬件在真实环境验收前补充，不以“看起来正常”代替记录。

自动化检查覆盖格式/步长处理、时间戳映射、状态恢复、队列边界和输出独立性。真实授权、设备与 OpenGL 测试单独标记；缺少环境导致跳过时应明确记录，不能算作通过。现有测试中的 Windows 专用断言需替换或删除，共用行为测试继续保留。

## 11. 首版不包含

- Windows/macOS 支持及跨平台兼容维护。
- 全发行版、所有 Wayland/X11 桌面环境兼容保证；独立的 X11 采集后端。
- 窗口采集专项验收、按应用音频采集、宿主机直接采集。
- ALSA 后端、原生 PipeWire 音频后端。
- DMA-BUF 零复制、VA-API/NVENC/QSV 硬件编解码及固定性能提升承诺。
- HDR、10 位视频、额外输出分辨率/帧率和其他新增产品功能。
