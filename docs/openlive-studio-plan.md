# OpenLiveStudio 项目方案

## 1. 项目目标

制作一个 Windows 桌面录制工具，支持摄像头和麦克风、实时画面滤镜、视频保存，并在基础版本稳定后考虑推流等扩展。

项目作为个人主项目，重点展示完整功能、稳定性、可复现的测试结果，以及对设计与实现的理解。AI 辅助实现，由你负责审核、验收和最终决策。

## 2. 基础版本范围

| 功能 | 预期结果 |
| --- | --- |
| 设备选择 | 可以选择摄像头和麦克风，设备不可用时有明确提示 |
| 实时预览 | 画面比例正确、颜色正常，预览流畅 |
| 画面滤镜 | 提供三个可独立开关、调整参数的滤镜 |
| 视频录制 | 可以开始和停止录制，保存的文件可正常播放 |
| 声音录制 | 录制文件包含清晰声音，无明显爆音或截断 |
| 音画同步 | 声音与画面对应，长时间录制无明显漂移 |
| 运行统计 | 展示录制时长、帧率和丢帧等必要信息 |
| 错误提示 | 设备断开、保存失败等情况有可理解的提示 |

目标为 1080p30，实际支持范围由目标机器与设备测试确认。先完成一条可用录制流程，再加入滤镜和性能优化。

## 3. 扩展版本

基础版本验收通过后，每次只选择一个扩展方向：

- 直播推流与断线恢复。
- 屏幕录制。
- 提高录制性能和设备适配能力。
- 增加滤镜。
- 截图或录制暂停与恢复。

这些功能不作为基础版本的交付前提。

## 4. 暂不包含的功能

- 多路画面组合与复杂场景编辑。
- 人脸处理与美颜。
- 完整播放器与播放列表。
- 跨平台支持。
- 4K60 录制。
- 多路声音混合。

## 6. 协作与审核

- AI 每轮只完成一个小步骤，通常修改 1–3 个业务文件。
- 每轮开始前明确目标、允许修改的文件和验收方式。
- AI 完成后说明改动、实际验证结果、操作方法和已知限制。
- 你审核并运行验收；发现问题就在当前步骤返工。
- 审核通过后再进入下一步，不自动连续完成整个阶段。
- 关键设计由你确认；不理解的实现先补充说明，再决定是否通过。
- 技术实现选择在执行相应步骤时单独讨论，不在本方案中预先展开。

## 7. Git 提交规则

- AI 完成代码后不自动提交。
- 你审核通过并明确要求提交后，AI 只提交当前步骤相关文件。
- 提交信息使用英文，不包含任务卡编号。
- 提交与推送分别处理；没有明确要求时不自动推送。

示例：

```text
feat(capture): add camera device selection
fix(recording): handle device disconnection
docs: update recording instructions
```

## 8. 验收标准

- 可以选择设备并进行实时预览，画面颜色和比例正常。
- 三个滤镜均可独立使用、调整参数和关闭。
- 可以反复开始、停止录制并生成可播放文件。
- 文件包含声音和画面，目标音画偏差小于 50ms，并有实测记录。
- 完成 10 分钟录制检查和 30 分钟长时间测试。
- 连续启停 20 次、最小化窗口和录制中退出均有验证。
- 设备断开或保存失败时能够提示并结束当前操作。
- 性能数据注明测试机器、设备、运行条件和结果。
- 所有未验证或未达到目标的内容明确记录。

## 9. 交付内容

- 可构建、可运行的项目。
- 构建与使用说明。
- 功能演示。
- 录制样例与验收记录。
- 性能测试结果与已知限制。
- 项目授权文件和第三方声明。
- 关键决策记录。

展示和简历只描述已经完成并验证的功能，数据使用实测结果，准确说明 AI 辅助与个人承担的工作。
