# OpenLive Studio 项目方案

## 1. 项目目标与依据

制作一个 Windows 桌面录制与直播工具，以 [UI 原型](openlive-studio-prototype.html) 为界面和交互参考，支持场景管理、多画面合成、声音混合、来源滤镜、本地录制和直播推流。

原型用于确定布局、操作入口和视觉风格；原型中的设备、动画画面、音频电平、录制、直播和运行指标包含模拟内容，不代表正式程序已有这些能力。正式程序逐步接入真实功能，未接入的操作禁用或明确标注，不能显示虚假的成功状态或运行数据。

AI 辅助实现，由你负责审核、验收和最终决策。具体小步骤见 [分步实施与 Review 路线](openlive-studio-roadmap.md)，现有测试骨架的使用方法见 [测试说明](../tests/README.md)。

来源、场景、多画面合成、混音器及模块职责的概念与演进方向见 [架构说明](openlive-studio-architecture.md)。其中区分当前实现与后续设计，不扩大本方案的功能范围。

## 2. 界面结构

默认布局：左侧场景和来源上下排列，左列延伸至底部；右侧上方为预览，下方从左到右依次为混音器、控制面板，最底部为状态栏。

| 区域 | 内容与行为 |
| --- | --- |
| 标题栏 | 产品名称、窗口操作 |
| 顶部操作区 | 视图、帮助等菜单入口；面板显隐、重置布局、关于 |
| 中央部件 | 合成画布、来源选中框和缩放手柄；保持画面比例，适应窗口大小 |
| 场景面板 | 场景列表、选择、添加、移除与顺序调整 |
| 来源面板 | 当前场景的来源列表、添加、移除、层级、显隐、锁定、属性和滤镜入口 |
| 混音器面板 | 每路音频的名称、电平、音量、静音与属性入口；通道固定宽度、紧凑靠左排列 |
| 控制面板 | 独立的录制、直播按钮和设置入口，三个按钮固定高度、纵向靠上排列，底部空白吸收剩余空间；不包含退出按钮或时长显示 |
| 状态栏 | 提示、独立 REC/LIVE 状态与时长、输出帧率、推流丢帧、发送码率和资源占用 |

场景、来源、混音器及控制共四个独立停靠面板。默认只有混音器和控制位于预览下方，场景与来源保留在左侧。面板支持移动、浮动、关闭和从视图菜单恢复，菜单勾选与显隐同步；重置布局恢复上述顺序与位置。关闭应用使用系统窗口关闭操作；REC/LIVE 时长统一在状态栏分别显示。

来源属性、变换、滤镜及全局设置使用独立对话框，不固定占用中央画布空间。顶部保留工具栏容器，操作内容以原型为准，不额外加入尚未计划的 OBS 功能。

### UI 架构

项目采用 **QML + Qt Widgets 混合架构**。保留 A1 已实现的主窗口外框，以 Widgets 承担主窗口、停靠面板容器和原生窗口管理；面板内部内容、动态控件、预览交互和对话框可以结合 QML 实现。

上述内容的具体分工在每步方案中确认，不将“使用停靠面板”等同于“面板内部全部使用 Widgets”，也不在当前文档中提前固定所有区域的实现方式。业务状态与媒体控制由 C++ 层统一管理，两类界面使用一致的数据和状态。

后续涉及 UI 的步骤，必须先说明 Widgets/QML 的职责、数据与操作的交互边界，以及对应验证方式。现有 A1 无需因本约定整体重写，新增区域和必要迁移按小步骤推进。详细约束见 [AGENTS.md](../AGENTS.md)。

## 3. 目标功能范围

以下是本轮路线的完整目标，按阶段交付，不要求第一轮全部实现。

| 功能 | 预期结果 |
| --- | --- |
| 场景管理 | 可以保存多套布局并切换；新增、重命名、移除、排序及重新打开后恢复 |
| 摄像头来源 | 选择真实设备及支持的画面模式，正确显示与关闭，失败有提示 |
| 显示器来源 | 选择显示器并采集画面；窗口采集和其他采集选项分步补充 |
| 图像来源 | 选择本地图像，保留透明区域与正确比例；按阶段支持原型列出的格式 |
| 文本来源 | 编辑内容、字体和字号，形成可参与合成的画面 |
| 多画面合成 | 多个来源组成同一输出画布，来源列表上方对应画面上层 |
| 来源变换 | 画布与列表联动选择，拖动移动、等比例缩放、数字编辑位置和尺寸、适应画布及右下角布局 |
| 显隐与锁定 | 隐藏来源不参与画面输出；锁定防止误移动和缩放，仍可明确解锁 |
| 来源滤镜 | 先实现调色的亮度、对比度、饱和度和开关；参数仅影响对应来源 |
| 音频采集与混合 | 先支持麦克风和桌面音频两路，各自音量、静音、电平及设备选择，混合到输出 |
| 本地录制 | 保存最终合成画面与混合声音，可开始、停止及重复录制，文件正常播放 |
| 直播推流 | 配置地址和密钥，可连接、开始、停止，显示真实连接状态 |
| 双输出 | 录制和直播可以单独或同时运行，独立计时、停止和报告错误 |
| 场景切换 | 点击其他场景立即直接切换，无动画、效果选择或时长设置；点击当前场景保留来源选择；后续接入输出时，切换不中断录制或直播 |
| 界面布局 | 面板显隐和布局恢复，重新启动后恢复用户停靠布局 |
| 设置与诊断 | 设置可校验、保存、取消；状态栏展示实测数据，设备与输出错误有提示 |

输出画布先以 1920×1080、30 fps 为目标，实际支持范围由目标机器与设备验证。图像、文本等静态来源先于真实采集接入，用于逐步验证合成与编辑。

## 4. 交互与数据规则

- 启动时创建一个默认空场景；至少保留一个场景，不因删除限制而清空最后一个场景的内容。删除需确认，取消、Esc 或关闭不删除；排序保留场景身份与选择。
- 新来源添加到列表顶部并选中，名称编号仅用于避免重名，不决定层级。同一场景内名称去除首尾空白后校验，英文不区分大小写；建议名称复用空缺编号，不同场景可以同名。
- 移除来源仅影响指定场景中的条目，不删除磁盘文件；确认前固定场景与来源，取消、Esc 或关闭不修改。移除选中来源后清除选择，允许空来源列表。
- 场景保存来源的摆放、层级、显隐和锁定状态。点击其他场景直接切换并清除来源选择，点击当前场景保留来源选择，无效目标不改变状态。预览接入后与列表同步切换，不保留错误的选中框。
- MVP 中各场景分别添加自己的来源；选择相同图像文件仍创建独立条目，不按文件路径自动共享业务状态，也不复制磁盘文件。条目名称、层级、显隐、锁定及后续摆放、滤镜属性分别管理，修改或移除一个条目不改变其他场景的条目。跨场景“复用已有来源”的数据结构与界面入口延后；接入摄像头等设备时，再在相应步骤明确同一设备跨场景使用及避免重复打开的规则。
- 原型中的 Logo、桌面与休息画面是演示内容；正式程序使用用户配置或明确的测试素材，不默认伪造已连接设备。
- 预览的选择边框、缩放手柄、工具提示和界面装饰不进入录像或直播画面。面板显隐不影响实际输出。
- 锁定来源后，鼠标、快捷键和变换对话框对位置、大小的修改使用一致规则。
- 属性、变换和全局设置采用确认后保存、取消不改变原值的方式。滤镜支持实时预览；实时变化立即生效，关闭窗口保留，后续如增加取消按钮则同时实现回滚。
- 每个来源只显示适用的滤镜；没有可用滤镜时给出空状态。音频滤镜后续单独加入，不把画面滤镜应用于纯音频。
- 同一设备的声音避免重复加入输出；辅助音频按实际添加的来源出现，不照搬原型中的固定模拟通道。
- 直播断开或停止不主动结束正常录制；录制失败或停止不主动结束正常直播。共同采集设备失效时分别报告受影响的输出。
- 录制与直播共用当前合成画面和混音结果；运行中修改布局和滤镜会影响两路输出，不提供未计划的独立直播画面。
- REC 与 LIVE 在状态栏分别计时，停止其中一路后，另一路继续计时；控制面板不重复显示时长。
- 修改正在使用的设备、输出画布或输出参数时，明确禁用或提示需要停止受影响输出，不能悄悄改变运行设置。
- 未接入真实统计时使用“—”或“未接入”；发送码率仅反映直播发送，不能在仅录制时显示模拟推流码率。
- 推流密钥默认遮蔽，不在状态提示或普通日志中展示明文。

## 5. 分阶段交付

| 阶段 | 目标 | 阶段结束时能展示什么 |
| --- | --- | --- |
| A | 主窗口与原型布局 | 原型布局、四个停靠面板及视图操作 |
| B | 场景与来源操作 | 用静态素材管理场景、来源、层级、显隐和锁定 |
| C | 合成画布与编辑 | 图像和文本真实合成，选择、移动、缩放及变换 |
| D | 摄像头与屏幕采集 | 用真实摄像头和显示器替换测试画面，形成画中画 |
| E | 来源滤镜 | 调色对所选来源实时生效，并保留正确输出效果 |
| F | 音频与混音器 | 麦克风和桌面声音真实采集、可调音量、可静音 |
| G | 音画同步录制 | 保存合成画面和混合声音，长时间录制可验证 |
| H | 直播与独立双输出 | 真实推流，录制与直播同时运行、独立启停 |
| I（暂缓） | 场景转场 | 当前默认直接切换；淡入淡出等转场能力不纳入本轮交付，重新启用前另行确认方案 |
| J | 设置与内容恢复 | 场景、来源、布局和有效设置可保存恢复 |
| K | 稳定性、统计与交付 | 实测指标、异常验证、演示及使用说明齐全 |

不再单独安排范围确认或开发基础阶段。必要准备随对应功能完成；先从原型窗口布局开始，随后逐步接入真实行为。

## 6. 后续扩展与原型占位

原型展示的选项不等于全部属于首批交付。尚未实现的选项不可点击后假装成功。

| 内容 | 实施安排 |
| --- | --- |
| 调色 | 当前路线实现；不再要求旧方案固定三个滤镜 |
| 色度键、锐化、暗角 | 保留滤镜扩展方向，逐个补充 |
| 跨场景来源复用 | 延后，不作为 MVP 或 B6 验收条件；暂不拆分共享来源与场景实例，不提供复用入口；同设备的采集生命周期随设备接入处理 |
| 直接切换 | 当前默认行为，无动画、时长或配置入口；后续随合成、录制与直播验证最终画面切换 |
| 淡入淡出 | 暂缓，不保留转场面板和效果选择入口；是否恢复及如何交互另行确认 |
| 其他转场 | 不纳入当前范围，不保留滑动、擦除等禁用占位，也不实现转场添加或管理入口 |
| MP4 录制 | 先支持并验证 |
| MKV、FLV、简单/高级输出模式 | 按后续需求补充，不复制无效设置 |
| 不同硬件编码设备与更多输出规格 | 先验证默认路线，再按目标设备扩展 |
| 窗口采集、额外采集方式、摄像头自带音频 | 单独实施，不与基础设备接入混在一起 |
| 辅助音频、应用音频、监听、音频滤镜与多音轨 | 基础两路混音完成后逐项扩展 |

暂不包含完整播放器、人脸处理、美颜、跨平台、4K60、嵌套场景、转场动画、转场添加与管理、复杂转场编辑、插件系统和完整 OBS 功能兼容。应用与 HTML 原型均已移除场景转场面板及其菜单入口，场景默认直接切换；原型不再包含淡入淡出动画。此项调整不代表真实合成、录制或直播输出已接通。

## 7. 协作方式

执行前先给方案并等待确认，实施后交付验证结果供你审核。详细流程、改动范围约束和 Git 提交约定统一维护在根目录 [AGENTS.md](../AGENTS.md)，本方案只维护产品目标与验收标准。

## 8. 验收标准

- 默认窗口布局与约定一致；四个停靠面板、视图菜单、关闭恢复与重置布局正常；关于窗口显示当前项目的真实信息。
- 场景与来源操作、层级、显隐、锁定、选择框和属性保持一致；空场景、最后一个场景与设备不可用均有明确行为。
- 图像、文本、摄像头和显示器画面可以合成；预览编辑坐标与输出画布一致，编辑标记不进入输出。
- MVP 中调色只影响指定场景的独立来源条目；同一路径不导致滤镜状态联动。后续加入跨场景来源复用时，再单独定义并验证共享属性的影响范围。
- 麦克风与桌面声音独立调节和静音；电平有真实含义，不重复采集同一路声音。
- 录制文件包含合成画面与混合声音；目标音画偏差小于 50ms，区分起始偏差与长期漂移并提供实测记录。
- 完成 10 分钟录制检查与 30 分钟长时间测试；连续启停 20 次，最小化或隐藏面板不中断输出。
- 录制与直播可单独或同时运行；分别停止、重新开始和输出失败时不误停另一条正常输出。
- 后续接入合成与输出后，场景直接切换出现在预览、最终录制及直播中，且不中断输出或重置输出时长。
- 设置确认、取消、无效值和重启恢复正常；运行期间不能错误应用不兼容参数。
- 设备断开、无写权限、磁盘写入失败、推流连接失败有提示，程序可受控结束或恢复。
- 实测数据注明机器、设备和运行条件；界面自动测试、图形测试、真实设备测试分别记录。

## 9. 交付内容

- 可构建、可运行的桌面项目，以及对应的 UI 原型。
- 原型入口到正式功能的完成情况、已禁用选项和已知限制。
- 构建与使用说明、测试运行说明。
- 多画面、混音、录制与直播的演示和验收记录。
- 录制样例、真实运行指标、同步与稳定性记录。
- 项目授权文件和第三方声明。

展示和简历只描述已经完成并验证的功能，准确说明 AI 辅助与个人承担的工作。
