# OpenLiveStudio 分步实施与 Review 路线

> 对应项目方案，面向“AI 实现、人工审核”的协作方式。
> 只描述目标、改动边界和验收结果，具体技术设计在执行相应步骤时另行讨论。

## 1. 执行规则

每个大阶段包含多个小步骤。默认每轮只执行一个小步骤，完成后等待你审核，不自动进入下一步。

- 每步只解决一个问题，通常修改 1–3 个业务文件。
- 必要的构建调整和验证文件计入范围，预计超过 5 个文件时先拆分。
- 约 100–200 行有效改动可作为进一步拆分的提醒，不作为硬指标。
- 开始前明确允许修改的文件；不顺手重构或修改其他功能。
- 每一步都应能够独立审核，并尽可能保持项目可构建、可运行。
- 新增功能先验证结果正确，再单独安排优化。
- 没有设备或运行条件时明确记录“未验证”，不代替你确认硬件效果。

每步交付：改动文件、改动说明、实际验证结果、手工验收方法、重点审核位置、已知限制。

审核顺序：**检查范围 → 阅读改动 → 构建 → 运行验收 → 通过或返工**。

## 2. 阶段 A：读取摄像头画面

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| A1 | 列出可用摄像头 | 接入本步所需依赖，项目能构建、启动；能识别设备，区分没有设备和读取失败 |
| A2 | 打开与关闭指定摄像头 | 能查看实际支持的画面模式，不支持的设置有明确反馈；关闭或打开失败时正确清理资源 |
| A3 | 持续读取摄像头画面 | 连续获得画面，停止或设备断开时能够结束 |
| A4 | 整理画面供后续使用 | 测试画面颜色、尺寸和方向正确，不同输入按约定处理 |

阶段闸门：目标摄像头能持续工作，先验证设备支持的模式，再验证目标清晰度和帧率。

## 3. 阶段 B：完成实时预览

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| B1 | 添加画面显示区域 | 先用静态测试图检查缩放和比例 |
| B2 | 让采集独立运行并可停止 | 读取画面时界面可操作，停止能结束等待且不遗留后台工作 |
| B3 | 显示实时画面 | 画面持续更新，界面较慢时不无限积压 |
| B4 | 添加设备选择与预览控制 | 可以选择设备、开始、停止和重新开始，关闭窗口正常 |

阶段闸门：能够演示实时预览，连续启停 20 次，并记录基本运行表现。

## 4. 阶段 C：完成纯视频录制

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| C1 | 验证画面可用于生成视频 | 使用可控测试画面验证输出正常，录制时间正确，结束时内容完整 |
| C2 | 生成可播放文件 | 保存 30 秒测试视频，播放器能够正常打开和播放 |
| C3 | 录制真实摄像头画面 | 录制内容从本次开始操作起算，可以创建独立的新录像 |
| C4 | 添加录制按钮和保存位置 | 开始、停止和再次录制可操作，保存完成后再提示成功 |

阶段闸门：摄像头可以录成可播放文件。失败时先修复录制，再继续增加功能。

## 5. 阶段 D：完成声音处理

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| D1 | 列出可用麦克风 | 能识别麦克风并查看实际设备条件 |
| D2 | 打开、读取和停止麦克风 | 持续获得声音，停止或设备断开时能够结束 |
| D3 | 整理声音供后续录制 | 声音长度正确，输入条件变化和结束时剩余内容有处理规则 |
| D4 | 独立验证声音输出 | 先用测试声音检查，再验证麦克风声音，无明显爆音或截断 |

阶段闸门：声音链路可单独验证，结果有记录。

## 6. 阶段 E：完成音画同步录制

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| E1 | 将测试画面与声音写入同一文件 | 文件有声音和画面，播放正常，能够完整结束 |
| E2 | 应用统一录制时间规则 | 统一声音与画面的时间表示，验证两路先后启动、输入中断和重新开始时的行为 |
| E3 | 接入真实摄像头与麦克风 | 完成一分钟录像，检查声音、画面和起始偏差；界面接线过多时另拆一步 |
| E4 | 处理长时间音画偏离 | 能监测并处理逐渐累积的偏差，模拟与实际验证分别记录 |
| E5 | 测量同步结果 | 在开头、中间和结尾检查对应事件，区分固定偏差与持续漂移 |

阶段闸门：先完成 10 分钟验证，再完成 30 分钟同步测试。未通过前不继续加入滤镜。

## 7. 阶段 F：建立独立画面处理能力

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| F1 | 建立不依赖窗口显示的处理流程 | 用测试图验证，最小化窗口时仍能继续处理 |
| F2 | 管理处理所需的画面资源 | 反复创建、使用和结束无异常，尺寸变化有明确限制 |
| F3 | 正确处理不同输入画面 | 测试图的颜色、方向和尺寸正确 |
| F4 | 支持处理步骤组合与全部关闭 | 关闭处理时结果符合预期，组合后结果可检查 |

阶段闸门：测试画面经过处理后正确，重复运行和结束无异常。

## 8. 阶段 G：接入录制并优化

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| G1 | 让处理后的画面可用于录制 | 保持正确颜色、方向和时间对应，先建立正确性基线 |
| G2 | 接入现有录制流程 | 与未处理录像比较，声音、时长和同步不受影响 |
| G3 | 优化画面传递效率 | 对比优化前后结果与性能，处理较慢时行为明确，结束时内容完整 |
| G4 | 接入实时预览 | 预览和录制都使用处理结果，界面较慢时不拖住录制 |

阶段闸门：完整音画录制稳定，性能优化有真实对比结果。

## 9. 阶段 H：逐个加入三个滤镜

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| H1 | 添加调色滤镜 | 默认效果自然，参数调整有效，极端设置无异常 |
| H2 | 添加模糊滤镜 | 画面效果正确，边缘表现一致，可独立关闭 |
| H3 | 添加暗角或边缘滤镜 | 二选一，效果正确，可独立关闭 |
| H4 | 添加参数界面 | 可以调整参数、开关和全部关闭，快速操作时保持稳定 |
| H5 | 验证单独与组合效果 | 使用固定测试图比较结果，实际录像能保留所选效果 |

阶段闸门：三个滤镜可独立使用和组合，并能稳定录入视频。

## 10. 阶段 I：稳定性、统计与交付

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| I1 | 完善失败后的恢复和结束行为 | 验证启动失败、重复停止、录制中退出和保存失败 |
| I2 | 验证处理过慢和积压情况 | 不无限增长内存，必要时明确报错并结束；每个已定位问题单独修复 |
| I3 | 添加运行统计 | 先显示时长、帧率和丢帧，再分步增加耗时信息，统计口径明确 |
| I4 | 完成长时间与异常测试 | 连续启停、最小化、设备拔出、10/30 分钟录制有记录，失败另开修复步骤 |
| I5 | 完成交付说明与演示 | 新环境可复现构建，使用说明、实测数据、已知限制和第三方声明齐全 |

阶段闸门：满足项目方案的基础版本验收标准。

## 11. 扩展版本

基础版本完成后只选一个方向，并继续按小步骤推进：

- 推流：先验证输出，再连接服务，再处理失败和恢复。
- 屏幕录制：先读取屏幕，再接入录制，再处理尺寸变化和稳定性。
- 性能与设备适配：先验证一个目标设备，再接入，再处理失败后的替代方案，最后做性能比较。

每个方向开工前另写小步骤，不和基础版本一起交给 AI 实现。

## 12. Git 提交规则

- AI 完成当前步骤后保持改动，等待你审核。
- 你明确要求提交后，只提交已经通过审核的相关文件。
- 提交信息使用英文，不包含步骤编号或任务卡编号。
- 默认不自动推送。

示例：

```text
feat(capture): add camera device selection
fix(recording): handle device disconnection
```

## 13. 给 AI 的执行模板

```text
请只执行分步实施路线中的 <当前步骤>。
目标：<一个具体结果>。
允许修改：<精确文件列表>。
前置条件：<已经完成并通过审核的内容>。
验收：<检查操作与预期结果>。

要求：
1. 开始前说明本步拟采用的实现方式和改动范围。
2. 不进入下一步，不顺手重构，不增加无关功能。
3. 预计超出文件范围时先提出拆分建议。
4. 不覆盖我的其他改动，不自动提交或推送。
5. 完成后给出改动说明、实际验证结果、手工验收方法、重点审核位置和已知限制。
6. 没有实际验证的内容明确标注。
完成后停止，等待我审核。
```

审核不通过时只列出当前步骤的问题、预期结果与允许修改的文件，让 AI 在当前范围内返工。

从 A1 的摄像头枚举开始，直接实现功能；必要的依赖配置、资源清理和时间处理随对应功能加入。设计问题随当前步骤解决，不单独安排前置文档审核阶段。实际执行时继续根据改动规模拆小，不要求一次完成表中所有内容。
