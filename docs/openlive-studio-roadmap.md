# OpenLive Studio 实施路线

> 以 [UI 原型](openlive-studio-prototype.html) 为布局和交互参考，对应 [项目方案](openlive-studio-plan.md)。
> 只描述目标、改动边界和验收结果；具体技术设计在执行相应步骤时说明。
> 概念、数据流与模块职责见 [架构说明](openlive-studio-architecture.md)，具体类与接口随对应步骤确认。渲染方向已确定为独立离屏 OpenGL 合成与 QOpenGLWidget 预览，按功能逐步接入。

## 1. 协作规则与当前起点

协作、方案确认、小步审核、验证与 Git 提交规则统一见根目录 [AGENTS.md](../AGENTS.md)。阶段表格不代表可以跳过方案确认；具体架构见 [架构说明](openlive-studio-architecture.md)，测试方法与记录见 [测试说明](../tests/README.md)。

- **已完成**：A1 至 A9（原 A5 的转场面板占位现已移除）、B1 至 B6，以及 C1 静态图像真实合成。A8 深浅主题定义、管理、偏好保存、界面接入和独立主题菜单均已完成；全屏预览仍取消，旧路线中的摄像头 A1 不再执行。
- **界面与状态**：采用 QML + Qt Widgets 混合架构，Widgets 承担主窗口、停靠容器与原生窗口管理，QML 展示内部内容；C++ StudioState 统一管理场景和来源状态。四个面板支持停靠、浮动、菜单恢复与重置，布局跨启动保存留到 J3。
- **已接通业务**：场景增删、重命名与排序，本地图像来源增删、层级、显隐和锁定。启动时为一个选中的空场景，不使用演示来源。各场景独立管理条目，来源行图标与提示表示当前状态，切换场景和面板重载后数据保持一致。
- **下一步 C2**：画布选择与来源列表选择双向联动；先给出实施方案并确认。C1 已接通独立合成线程、共享纹理和真实预览，跨场景来源复用继续延后。
- **已接通预览／尚未接通编辑与输出**：图像按比例适应画布并按层级合成，显隐和场景切换同步更新画面；透明预览纹理与黑底输出纹理分离。画布选择、拖动、缩放和锁定对变换的限制留到 C2 至 C5。混音器、录制、直播及设置仍未接入业务，相关入口保持禁用，统计不模拟成功状态。
- **转场面板调整**：应用与 HTML 原型均已移除转场面板、视图菜单入口及相关资源，底部为混音器和控制。场景默认直接切换；淡入淡出等转场能力暂缓，阶段 I 不作为本轮交付要求。
- **原型差异**：HTML 原型尚未同步 B3 至 B5 的新增交互，原型演示不代表实际采集、合成或输出能力。
- **验证边界（2026-10-25 更新）**：本机 Qt 6.12.0、MSVC 2022 x64 Ninja Debug 构建、核心与真实 GPU 图形专项测试已通过；主题、透明预览、上下文释放及不同 DPI 的原生截图已检查。UI CTest 总时限已由 90 秒提高到 120 秒，连续三次通过，耗时 57.27、115.82、118.28 秒，后两次余量较小，耗时波动仍待排查。NVIDIA/WGL 偶发上下文共享失败仍未修复，单次复跑通过不代表问题消失。真实采集设备、媒体输出、原生悬停提示及 GitHub 托管 CI／Qt 6.8.3 仍未验证；详见 [测试说明](../tests/README.md)。

默认左侧场景和来源上下排列并延伸至底部；预览下方从左到右为混音器、控制两个独立停靠面板，最底部为状态栏。混音器通道紧凑靠左，控制按钮固定高度、纵向靠上，底部空白吸收余量。

| A2（已完成） | 添加场景面板 | 独立停靠面板与列表、增删和排序入口；暂不接场景业务，按钮状态准确 |

| A4（已完成） | 添加混音器面板 | 预览下方最左侧的独立面板，桌面音频与麦克风通道固定宽度、靠左排列并显示未接入；操作入口禁用、空电平槽不模拟声音，支持滚动、停靠和加载失败恢复 |

| A8（已完成） | 深色与浅色主题 | 两套语义配色、C++ 统一主题管理、Widgets/QML 同步切换并保存用户选择；独立“主题”菜单，保存失败保持原主题并提示；预览底色与输出分离，不包含自定义颜色或系统跟随 |

阶段验收：主窗口可按原型演示布局与视图行为，保持现有测试通过，并为面板恢复等关键交互补充验证。

A8 按以下小步骤分别实施和审核，主题定义及架构约定见 [项目方案](openlive-studio-plan.md#深色与浅色主题)：

1. **主题定义与资源（已完成）**：新增 `assets/themes/dark.json`、`light.json`，以相同语义结构定义颜色并打包为 Qt 资源；验证结构、颜色、文字对比度及资源读取。界面不变，不读取或保存用户配置。
2. **主题管理与保存（已完成）**：C++ `ThemeManager` 加载并校验主题，通过用户配置目录中的 INI 保存主题名称；覆盖缺失或无效配置、默认深色与重启恢复。
3. **界面接入（已完成，分步审核）**：Widgets 外框与现有 QML 面板、对话框共享同一主题实例，替换硬编码颜色；验证普通、选中、悬停、焦点和禁用状态，测试使用同一套资源。
4. **切换入口与验收（已完成）**：独立“主题”顶级菜单提供深色、浅色选择，已验证即时切换、菜单状态、重启恢复、保存失败回退、浮动面板和图标可见性。原生预览使用 JSON 的 `preview.canvas` 与 `preview.surrounding`；浅色预览底色不改变真实黑色图像像素或黑底输出纹理。

## 3. 阶段 B：场景与来源操作

B1 至 B5 已完成并提交：来源增删、逐项层级调整、显隐与锁定状态及对应面板交互均已接通。B5 测试覆盖无效目标和移动边界、稳定身份与选择、模型通知、场景隔离、状态切换及面板重载；新增两个 Lucide 图标已按固定提交导入并保留来源与许可证记录，四种图标的正常／禁用软件渲染已验证。本阶段完成真实文件引用及场景内条目状态管理；图像预览合成随后已由 C1 接通，锁定对变换的限制仍随 C3 至 C5 实现。B6 场景直接切换与数据独立性验证已完成并通过用户审核；使用生成图像检查同文件的独立条目、增删与状态隔离、反复切换及空场景，使用真实 MainWindow 面板检查点击当前场景保留选择、切换其他场景清除选择、排序与显隐锁定恢复、失败恢复及重载。现有业务实现满足这些测试，无需修改业务代码，也未引入共享来源结构或复用入口。本机 Ninja Debug 构建及新增专项测试通过；完整 CTest 3/3 通过，界面测试 56.49 秒，总计 56.75 秒，详细记录见 [测试说明](../tests/README.md)。B6 后的 C1 已完成，下一功能步骤为 C2，仍需先给出实施方案并确认。HTML 原型尚未同步 B3 至 B5 的新增交互。

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| B1（已完成） | 接入单场景与来源列表 | 默认空场景已选中，两个列表使用共享状态并支持点击选择与高亮；切换场景更新来源并清除来源选择，空状态正确；多场景及来源交互使用测试数据验证 |

## 4. 阶段 C：合成画布与编辑

遵循 [OpenGL 合成与预览架构](openlive-studio-architecture.md#opengl-composition-and-preview-architecture)：C++ 场景状态向独立合成线程提供快照，`QOffscreenSurface + QOpenGLContext` 产生干净画面，`QOpenGLWidget` 通过共享纹理与同步显示结果并处理画布交互；编辑标记仅进入预览。QML 面板继续通过 C++ 状态交互，与预览统一 OpenGL 图形后端。C1 已分步完成并提交，涵盖图像合成、共享纹理、合成线程、预览控件、场景快照及主窗口集成；后续编辑步骤继续明确资源生命周期和验证范围，不提前实现 D 至 H 的媒体功能。离屏软件 UI 测试不能替代真实 OpenGL 合成、共享纹理、窗口缩放与资源清理验证；最小化后持续输出随 G、H 验证。

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| C1（已完成） | 让静态图像参与真实合成 | 图像按比例适应画布，透明及半透明正确，多来源按层级显示；显隐、切换场景、窗口缩放和错误恢复已接通；预览专用底色不改变黑底输出纹理 |
| C2 | 接通画布选择与列表选择 | 双向联动，点击空白取消选择，隐藏来源没有错误选中框 |
| C3 | 实现来源拖动 | 坐标按画布含义更新，调整窗口大小后拖动仍准确，锁定时不可移动 |
| C4 | 实现缩放手柄 | 等比例缩放、合理最小尺寸，锁定时不可缩放；超出文件预算继续拆分 |
| C5 | 添加变换对话框 | X/Y、宽高、适应画布、右下角布局；确认应用、取消保留原值，锁定规则一致 |
| C6 | 添加文本来源与属性 | 修改文本、字体、字号后真实更新合成内容；空文本与取消有确定行为 |
| C7 | 接入编辑快捷键 | Delete 移除、Ctrl+E 变换、方向键移动、Shift 加大步长；输入文字时不误删或误移动来源 |

阶段验收：用图像和文本完成静态多画面编辑，选中框、手柄和界面提示与最终画面分离。

## 7. 阶段 F：音频与混音器

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| F1 | 枚举音频设备并接入属性 | 区分输入设备和播放设备；先支持麦克风、桌面音频，辅助通道不凭空出现 |
| F2 | 读取真实麦克风声音 | 打开、持续采集、停止和断开均可验证；先单独验证清晰声音 |

## 8. 阶段 G：音画同步录制

| 步骤 | 本步目标 | 可审核的交付与验收 |

| G2 | 生成完整可播放录像 | 设置保存位置，先支持 MP4，正常停止后文件完整，写入失败有提示 |
| G3 | 加入可控测试声音 | 检查音画对应与先后启动，不直接用两路时长相等代替同步验证 |
| G4 | 接入真实合成与混音 | 录制包含设备、布局、来源滤镜和混合声音，预览与输出一致 |
| G5 | 接通录制控制与时间显示 | 开始、停止、再次录制，录制中退出、无效路径和失败恢复正确 |
| G6 | 验证长期同步与稳定性 | 测开头、中间、结尾事件，区分固定偏差和漂移；先 10 分钟，再 30 分钟 |

阶段验收：完成多画面和混音录制。最小化窗口、关闭面板不影响输出；音画偏差有真实测试记录。

## 9. 阶段 H：直播与独立双输出

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| H1 | 保存并校验直播设置 | 地址、密钥和有效输出参数可配置；密钥遮蔽，取消不保存，运行中设置有明确限制 |
| H2 | 接通单次真实直播 | 本地服务端可以接收并播放合成画面和混合声音，启停和连接失败有明确结果 |
| H3 | 同时开启录制与直播 | 两个按钮独立，顺序不限，不重复启动共同采集；文件和直播内容分别验证 |
| H4 | 验证独立停止与重新开始 | 停直播不断录像，停录制不断直播；分别计时，再次启动一条输出不重置另一条 |
| H5 | 处理推流异常与恢复 | 超时或断线不拖住录制；恢复连接后行为明确；错误与恢复提示对应真实状态 |

阶段验收：覆盖仅录制、仅直播、同时运行和分别停止四类状态，不能以互斥模式替代。

## 10. 阶段 I：场景转场（暂缓）

场景转场能力暂缓，不纳入本轮交付；不保留效果选择、时长、执行按钮或转场管理入口。原 I1–I3 的效果选择、剪切和淡入淡出实施安排暂停，重新启用前另行确认范围、交互和验收方案。

当前默认行为是直接切换：点击其他场景立即切换并清除来源选择，点击当前场景保留选择，无效目标不改变状态。B6 已验证场景状态和来源列表切换；C1 已接通真实图像预览的直接切换；录制和直播中的直接切换仍分别随阶段 G、H 验证。

后续输出验收仍需检查：切换后录制文件与接收端显示当前场景内容，录制和直播持续运行，输出时长不重置。上述要求不代表输出功能已经实现，也不要求实现转场动画。

## 12. 阶段 K：稳定性、统计与交付
