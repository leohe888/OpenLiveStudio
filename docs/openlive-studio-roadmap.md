# OpenLive Studio 分步实施与 Review 路线

> 以 [UI 原型](openlive-studio-prototype.html) 为布局和交互参考，对应 [项目方案](openlive-studio-plan.md)。
> 只描述目标、改动边界和验收结果；具体技术设计在执行相应步骤时说明。

## 1. 协作规则与当前起点

当前 A1 至 A7、A9 已完成，A8 已取消，阶段 A 的实施已完成。主窗口包含菜单、工具栏容器、中央预览占位和状态栏；场景与来源面板在左侧上下排列并延伸至底部，预览下方从左到右为混音器、场景转场、控制面板，由 Widgets 提供独立停靠容器、QML 展示内部内容。B1 已完成，启动时创建并选中一个名为“场景”的空场景，来源列表显示“暂无来源”；两个列表共享状态，点击选择与高亮同步，切换场景会更新来源列表并清除来源选择；B2 已完成，场景面板“＋”已启用，双击场景行可重命名；B3 已完成，删除入口按剩余场景数量启用，上移与下移入口按当前项位置启用；来源面板有添加、移除、上移、下移、滤镜和属性六个禁用入口，来源行模板预留显隐与锁定按钮，不显示演示来源。

场景名称对话框预填并选中建议名称或原名称；首尾空白会去除，空名称及重复名称（英文不区分大小写）会提示错误。确认添加后选中新空场景，重命名保留场景 ID、来源和选择状态；取消、Esc 和关闭均不保存。两个列表在溢出时持续显示竖向滚动条，全部内容可见时隐藏；支持滚轮与拖动，缩放后自动更新，底部操作栏固定，滚动不改变选择。

删除入口打开当前场景的确认对话框，默认聚焦取消；取消、Esc 或关闭不删除。确认针对打开对话框时的场景 ID，目标已失效或仅剩一个场景时显示错误并保留对话框。至少保留一个场景，不自动清空其内容；删除当前场景后优先选中下一项，删除末项时选中上一项，并清除来源选择。上移、下移每次移动一行，保持场景 ID、来源和选择状态；首项不能上移，末项不能下移。面板重载后删除与排序入口仍可用。

A8 主题切换已取消，保持当前界面配色；全屏预览也已取消，菜单中已移除入口，相关原型入口与快捷键不纳入实现与验收。A9 关于窗口可从帮助菜单打开，显示 OpenLive Studio、运行时 Qt 版本及应用版本；未设置应用版本号时显示“开发版本（未设置版本号）”。窗口打开期间重复触发会激活已有窗口，关闭按钮、Esc 和关闭后重开均已验证。系统标题栏继续承担最小化、最大化和关闭操作。

关于窗口使用 QML 展示内容，Widgets 承担原生对话框容器，通过主窗口的统一对话框入口传入信息并处理关闭。对话框加载失败会显示错误提示，关闭后释放内容；后续对话框可按对应步骤复用该入口。

混音器显示桌面音频和麦克风两个通道区域，固定宽度、紧凑靠左排列，均标注“未接入”；音量滑杆、静音及属性入口保持禁用，电平槽为空、数值显示“—”，不模拟声音或设备状态。面板采用紧凑高度，小尺寸下内容可滚动。真实设备枚举、采集、音量、静音与混音业务留到阶段 F。

场景转场面板位于混音器和控制面板之间，包含效果选择、时长和贴底的转场按钮，均保持禁用。效果列表包含淡入淡出、剪切、滑动和擦除，当前未选中并显示“未接入”；时长显示原型默认值 300 ms，尚未连接业务或保存配置。实际转场留到阶段 I。

控制面板位于底部最右侧，仅保留独立的录制、直播按钮及设置入口，固定高度、纵向靠上排列，底部弹性空白吸收剩余空间。三个按钮均禁用，尚未接入后端或设置窗口；面板不包含退出按钮、退出请求或时长，REC／LIVE 时长仅在状态栏占位。小尺寸下内容可滚动。五个面板支持浮动、重新停靠、关闭和加载失败恢复；视图菜单可恢复面板，勾选与显隐同步。启动和重置使用相同的默认布局，重置可恢复移动、标签合并、浮动或隐藏的面板，保持主窗口尺寸与 QML 实例；布局跨启动保存留到 J3。

控制面板此前的宽度与高度绑定循环已修复，回归测试会将此类警告判为失败。当前测试与软件渲染日志未发现绑定循环警告。

Qt Test 与 CTest 骨架已完成，现有测试覆盖窗口启闭、基本结构、缩放后的输出状态可见性、五个 QML 面板的加载与初始状态、默认停靠布局、停靠操作、菜单显隐同步、全部隐藏后的菜单恢复、重置布局与重复重置、加载失败提示与恢复，以及十二个图标的资源解码和正常／禁用状态渲染。混音器测试另覆盖未接入通道、禁用滑杆、紧凑高度、滚动范围及拉宽后通道保持靠左；转场测试覆盖禁用状态、缩放与按钮贴底；控制测试覆盖三个固定高度的纵向按钮、底部弹性空白、小尺寸滚动，以及退出入口和面板时长已移除。正式程序不加入演示来源，多场景和有来源时的交互使用可控测试数据验证。新增对话框测试覆盖初始数据、关闭与释放、加载异常、关于信息、重复打开和关闭后重开。B3 四轮已完成，本机 Debug 构建通过，状态测试报告 24 项通过（含初始化与清理）。删除确认对话框的确认、取消、Esc、关闭、失效目标与最后一个场景用例通过；面板删除与排序的首次加载、重载两个数据用例通过，覆盖多场景滚动列表和边界按钮状态。最新完整 CTest 为 2/2 通过。B3 期间部分 CTest 运行曾达到 30 秒时限，单独完整界面测试通过，第四轮完整 CTest 通过且未放宽时限；本机运行耗时仍有波动。名称对话框、滚动条、删除确认与错误状态，以及排序前后按钮状态的软件渲染截图已检查。此前默认／最小主窗口、默认场景、来源空状态、选中测试来源及关于窗口的软件渲染检查已通过。真实 GPU 渲染、实际媒体处理和设备功能尚未验证。测试方法见 [测试说明](../tests/README.md)。

场景与来源状态由 C++ StudioState 统一管理；MainWindow 负责创建、生命周期和向面板提供共享状态，QML 负责列表展示与点击交互。面板重新加载后保持状态一致，窗口销毁时先释放面板内容、再释放共享状态。MainWindow 转接名称与删除确认对话框请求；名称校验、场景增删与排序、选择回退及按钮可用状态由 StudioState 管理，QML 展示状态并发起操作。来源操作、真实媒体处理与配置保存仍由后续步骤实现。

Windows CI 配置已完成，包含推送到 main、Pull Request 和手动触发，使用 Qt 6.8.3、MSVC 2022 x64 构建 Debug 并运行 CTest，缓存 Qt 并保存测试日志。本机使用 Qt 6.12.0 已通过相同 Visual Studio 多配置构建与测试命令；GitHub 托管环境及 CI 指定的 Qt 6.8.3 尚未验证，需首次线上运行确认。CI 不包含打包、发布或真实设备验证。

先给方案、确认后实施、小步审核、验证交付及 Git 提交规则统一见根目录 [AGENTS.md](../AGENTS.md)。每个阶段的表格仅定义功能步骤与验收结果，不代表可以跳过实施前的方案确认。

不再执行旧路线中的摄像头 A1；新版 A1 从原型主窗口布局开始。没有独立的设计确认或通用开发基础阶段。

后续采用 **QML + Qt Widgets 混合架构**：保留已完成的 Widgets 主窗口外框与停靠容器，内部内容的技术分工随当前步骤确认。每次 UI 方案应明确两者的职责、数据与操作交互边界及验证方式，具体约定见 [AGENTS.md](../AGENTS.md)。路线中的“面板”“对话框”和“控件”不隐含必须全部使用 Widgets。

## 7. 阶段 F：音频与混音器

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| F1 | 枚举音频设备并接入属性 | 区分输入设备和播放设备；先支持麦克风、桌面音频，辅助通道不凭空出现 |
| F2 | 读取真实麦克风声音 | 打开、持续采集、停止和断开均可验证；先单独验证清晰声音 |

| G1 | 保存可控合成画面 | 用固定或生成素材验证视频输出，时间正确，编辑边框不进入文件 |
| G2 | 生成完整可播放录像 | 设置保存位置，先支持 MP4，正常停止后文件完整，写入失败有提示 |
| G3 | 加入可控测试声音 | 检查音画对应与先后启动，不直接用两路时长相等代替同步验证 |
| G4 | 接入真实合成与混音 | 录制包含设备、布局、来源滤镜和混合声音，预览与输出一致 |
| G5 | 接通录制控制与时间显示 | 开始、停止、再次录制，录制中退出、无效路径和失败恢复正确 |
| G6 | 验证长期同步与稳定性 | 测开头、中间、结尾事件，区分固定偏差和漂移；先 10 分钟，再 30 分钟 |

阶段验收：完成多画面和混音录制。最小化窗口、关闭面板不影响输出；音画偏差有真实测试记录。

## 9. 阶段 H：直播与独立双输出

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| H1 | 保存并校验直播设置 | 地址、密钥和有效输出参数可配置；密钥遮蔽，取消不保存，运行中设置有明确限制 |
| H2 | 接通单次真实直播 | 本地服务端可以接收并播放合成画面和混合声音，启停和连接失败有明确结果 |
| H3 | 同时开启录制与直播 | 两个按钮独立，顺序不限，不重复启动共同采集；文件和直播内容分别验证 |
| H4 | 验证独立停止与重新开始 | 停直播不断录像，停录制不断直播；分别计时，再次启动一条输出不重置另一条 |
| H5 | 处理推流异常与恢复 | 超时或断线不拖住录制；恢复连接后行为明确；错误与恢复提示对应真实状态 |

阶段验收：覆盖仅录制、仅直播、同时运行和分别停止四类状态，不能以互斥模式替代。

## 10. 阶段 I：场景转场

## 11. 阶段 J：设置与内容恢复

| 步骤 | 本步目标 | 可审核的交付与验收 |

## 12. 阶段 K：稳定性、统计与交付

| K4 | 完成系统验收 | 连续启停 20 次、10/30 分钟录制、双输出、场景切换、最小化与停靠操作有记录 |

阶段验收：满足项目方案目标，自动测试与人工设备验收分开记录。只有全部目标达到后才宣称相应功能完成。
