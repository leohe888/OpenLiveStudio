# OpenLive Studio 实施路线

> 以 [UI 原型](openlive-studio-prototype.html) 为布局和交互参考，对应 [项目方案](openlive-studio-plan.md)。
> 只描述目标、改动边界和验收结果；具体技术设计在执行相应步骤时说明。
> 概念、数据流与模块职责见 [架构说明](openlive-studio-architecture.md)，具体类与接口随对应步骤确认。

## 1. 协作规则与当前起点

协作、方案确认、小步审核、验证与 Git 提交规则统一见根目录 [AGENTS.md](../AGENTS.md)。阶段表格不代表可以跳过方案确认；具体架构见 [架构说明](openlive-studio-architecture.md)，测试方法与记录见 [测试说明](../tests/README.md)。

- **已完成**：A1 至 A7、A9，以及 B1 至 B5。A8 主题切换和全屏预览已取消，不纳入后续验收；旧路线中的摄像头 A1 不再执行。
- **界面与状态**：采用 QML + Qt Widgets 混合架构，Widgets 承担主窗口、停靠容器与原生窗口管理，QML 展示内部内容；C++ StudioState 统一管理场景和来源状态。五个面板支持停靠、浮动、菜单恢复与重置，布局跨启动保存留到 J3。
- **已接通业务**：场景增删、重命名与排序，本地图像来源增删、层级、显隐和锁定。启动时为一个选中的空场景，不使用演示来源。各场景独立管理条目，来源行图标与提示表示当前状态，切换场景和面板重载后数据保持一致。
- **下一步 B6**：验证场景直接切换、来源列表与选择更新，以及各场景的数据独立性，尚未标记完成。跨场景来源复用延后，不引入共享来源结构或复用入口；摆放编辑和转场动画不属于本步。
- **尚未接通**：中央预览仍为占位，真实合成与变换编辑留到阶段 C；隐藏对输出的影响、锁定对移动和缩放的限制随对应功能验证。混音器、转场、录制、直播及设置仍未接入业务，相关入口保持禁用，统计不模拟成功状态。
- **原型差异**：HTML 转场演示仅保留剪切和淡入淡出，无执行按钮，点击其他场景触发所选效果；应用面板仍有旧选项及禁用执行按钮，尚待同步。HTML 原型尚未同步 B3 至 B5 的新增交互，原型演示不代表实际采集、合成或输出能力。
- **验证边界**：本机 Qt 6.12.0、MSVC 2022 x64 的 Ninja Debug 构建及完整 CTest 3/3 通过，界面验证使用离屏软件渲染。真实 GPU、设备与媒体输出、原生悬停提示，以及本轮 HTML 转场的实际浏览器显示未验证。Windows CI 已配置，GitHub 托管环境及指定的 Qt 6.8.3 待首次线上验证。

## 10. 阶段 I：场景转场

本阶段仅提供剪切（Cut）与淡入淡出（Fade），两种效果默认可选，无需添加。剪切立即切换，无过渡动画，时长控件禁用且不参与切换计算；淡入淡出使用可调时长，初始值沿用 300 ms。滑动、擦除及其他效果不在当前范围，不保留禁用选项，也不加入“＋”或转场管理入口。转场面板仅配置效果和时长，不保留执行按钮；点击场景列表中的其他场景即触发所选效果，点击当前场景不执行，动画期间忽略重复切换请求。当前已完成的 A5 仍是禁用面板占位；选项同步与业务接入分别验证。

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| I1 | 明确选择与转场操作 | 效果列表仅含默认提供的剪切、淡入淡出，无添加入口或执行按钮；点击其他场景直接按所选效果切换，点击当前场景及单场景不误操作；动画期间忽略重复切换请求 |
| I2 | 实现剪切（直接切换） | 立即切换，无动画；时长控件禁用且不影响切换；来源与声音规则一致，录制和直播继续，输出内容切换正确 |
| I3 | 实现淡入淡出与时长 | 选择淡入淡出时启用时长控件，按用户时长过渡实际合成内容；切换到剪切后不丢失淡入淡出的时长设置，连续点击受控，实际过渡进入录制与直播输出 |

阶段验收：无添加入口或执行按钮，点击场景列表直接触发所选的剪切、淡入淡出；剪切立即切换且不受时长影响，淡入淡出遵循设置时长。切换与动画可以在录制文件和接收端看到，预览操作不重置输出时长。

| 步骤 | 本步目标 | 可审核的交付与验收 |

| J1 | 完善原型设置窗口 | 整理已接入的录制、直播、画布和帧率选项；确认保存、取消保留原值，无效参数有提示；未实现选项禁用 |
| J2 | 保存场景、来源及其属性 | 重新启动后布局、素材引用和滤镜正确恢复；找不到文件或设备时保留配置并提示 |
| J3 | 保存停靠布局 | 重新打开后恢复用户停靠布局；重置布局可恢复可用窗口，不恢复到屏幕外 |
| J4 | 验证配置异常与退出 | 无效或缺失配置可以回到可用默认状态；运行中退出受控结束，不保存假成功或假连接状态 |

阶段验收：原型中的有效设置成为真实可恢复配置；示例路径、设备、版本和模拟数据不直接进入成品。

## 12. 阶段 K：稳定性、统计与交付

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| K1 | 接入真实输出统计 | REC/LIVE 时长、帧率、推流丢帧和发送码率含义明确；未接入指标用空状态；可继续按指标拆步 |
| K2 | 接入资源占用与诊断 | CPU、内存与错误信息有真实来源，提示不泄露密钥；不沿用原型随机数据 |
| K3 | 验证输出失败与积压 | 设备断开、写入失败、网络慢或断开时不无限增长内存；单路故障不误停正常输出；按定位问题分别修复 |
| K4 | 完成系统验收 | 连续启停 20 次、10/30 分钟录制、双输出、场景切换、最小化与停靠操作有记录 |
| K5 | 完成交付说明 | 构建、测试、使用、原型对应情况、设备条件、实测指标、已知限制和第三方声明齐全 |

阶段验收：满足项目方案目标，自动测试与人工设备验收分开记录。只有全部目标达到后才宣称相应功能完成。
