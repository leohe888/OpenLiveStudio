# OpenLive Studio 分步实施与 Review 路线

> 以 [UI 原型](openlive-studio-prototype.html) 为布局和交互参考，对应 [项目方案](openlive-studio-plan.md)。
> 只描述目标、改动边界和验收结果；具体技术设计在执行相应步骤时说明。

## 1. 协作规则与当前起点

当前应用仍是空主窗口；Qt Test 与 CTest 骨架已完成，现有测试仅验证窗口创建、显示和关闭，不代表原型功能已实现。测试方法见 [测试说明](../tests/README.md)。

先给方案、确认后实施、小步审核、验证交付及 Git 提交规则统一见根目录 [AGENTS.md](../AGENTS.md)。每个阶段的表格仅定义功能步骤与验收结果，不代表可以跳过实施前的方案确认。

不再执行旧路线中的摄像头 A1；新版 A1 从原型主窗口布局开始。没有独立的设计确认或通用开发基础阶段。

## 2. 阶段 A：主窗口与原型布局

默认左侧场景和来源、中间预览、右侧混音器和场景转场、底部控制及状态栏。控制面板默认呈原型底部横条，仍可独立停靠。

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| A1 | 搭建主窗口外框 | 产品标题、顶部菜单与工具栏容器、中央预览占位和状态栏；窗口缩放无重叠，统计使用未接入状态 |
| A2 | 添加场景面板 | 独立停靠面板与列表、增删和排序入口；暂不接场景业务，按钮状态准确 |
| A3 | 添加来源面板 | 独立停靠面板、来源列表和显隐、锁定、层级、属性、滤镜入口，不伪造真实采集 |
| A4 | 添加混音器面板 | 麦克风和桌面声音的通道布局、滑杆、静音与属性入口；电平未接入时不随机跳动 |
| A5 | 添加场景转场面板 | 效果、时长和转场入口；未支持的效果禁用 |
| A6 | 添加控制面板 | 录制、直播、设置和退出入口；录制与直播独立，后端未就绪时不假装启动 |
| A7 | 接通面板与视图操作 | 五个面板关闭、菜单恢复、移动、浮动与重置布局正常；菜单勾选和面板状态一致 |
| A8 | 添加主题切换 | 深色、浅色、跟随系统；菜单选择与实际外观一致，画布内容颜色不受影响 |
| A9 | 接通全屏预览与窗口操作 | F11 切换，Esc 退出全屏预览，恢复原布局；关于窗口显示当前项目而非原型示例版本 |

阶段验收：主窗口可按原型演示布局与视图行为，保持现有测试通过，并为面板恢复等关键交互补充验证。

## 3. 阶段 B：场景与来源操作

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| B1 | 接入单场景与来源列表 | 当前场景决定来源列表，切换选择不会串到其他场景，空列表有正确状态 |
| B2 | 支持添加和重命名场景 | 默认创建空场景；名称校验，选择状态正确，不默认伪造主场景素材 |
| B3 | 支持删除与调整场景顺序 | 明确至少保留一个默认空场景；删除当前场景后合理切换，按钮在边界禁用 |
| B4 | 支持添加、移除图像来源 | 通过原型添加对话框选择类型、名称和文件；取消、无效文件、无选中来源有合理行为 |
| B5 | 接入来源层级、显隐和锁定 | 列表上方是画面上层；操作对应正确来源，数据与界面一致 |
| B6 | 接入场景切换与来源复用 | 各场景摆放独立，同一来源复用规则明确，切换清除无效选择；先直接切换，不加入转场动画 |

阶段验收：用本地图像完成两套可切换布局，原型的场景与来源入口开始操作真实内容。

## 4. 阶段 C：合成画布与编辑

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| C1 | 让静态图像参与真实合成 | 保持比例与透明区域，多个来源按层级显示，画布适应窗口 |
| C2 | 接通画布选择与列表选择 | 双向联动，点击空白取消选择，隐藏来源没有错误选中框 |
| C3 | 实现来源拖动 | 坐标按画布含义更新，调整窗口大小后拖动仍准确，锁定时不可移动 |
| C4 | 实现缩放手柄 | 等比例缩放、合理最小尺寸，锁定时不可缩放；超出文件预算继续拆分 |
| C5 | 添加变换对话框 | X/Y、宽高、适应画布、右下角布局；确认应用、取消保留原值，锁定规则一致 |
| C6 | 添加文本来源与属性 | 修改文本、字体、字号后真实更新合成内容；空文本与取消有确定行为 |
| C7 | 接入编辑快捷键 | Delete 移除、Ctrl+E 变换、方向键移动、Shift 加大步长；输入文字时不误删或误移动来源 |

阶段验收：用图像和文本完成静态多画面编辑，选中框、手柄和界面提示与最终画面分离。

## 5. 阶段 D：摄像头与屏幕采集

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| D1 | 枚举摄像头并接入属性窗口 | 随本步接入所需依赖；真实设备列表可刷新，区分没有设备与枚举失败 |
| D2 | 打开与关闭摄像头来源 | 选择设备和支持模式；取消不应用，打开失败可恢复，反复打开关闭能清理 |
| D3 | 摄像头画面进入合成 | 动态画面取代占位素材，颜色、方向、比例正确；不阻塞界面 |
| D4 | 枚举并采集显示器 | 从属性窗口选择真实显示器，打开失败有提示；先只实现显示器采集 |
| D5 | 合成桌面与摄像头 | 桌面为背景、摄像头画中画并叠加图像或文本；某路变慢不无限积压 |
| D6 | 验证切换与设备异常 | 同源跨场景复用不重复打开设备；设备断开、来源移除、退出和最小化行为明确 |

阶段验收：原型主场景可以替换为真实屏幕、摄像头和用户素材，设备控制随功能补齐。

## 6. 阶段 E：来源滤镜

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| E1 | 接入来源滤镜窗口与开关 | 列表入口对应当前来源；没有适用滤镜时为空状态；占位滤镜不可假装启用 |
| E2 | 实现亮度调整 | 用固定测试图验证默认和极端参数，只影响指定来源 |
| E3 | 增加对比度与饱和度 | 与亮度组合正常；每个来源保存自己的参数，不复用原型的单份全局摄像头参数 |
| E4 | 验证实时参数与共享来源行为 | 实时预览、关闭窗口保留效果；共享来源影响范围明确，不修改其他独立来源 |

阶段验收：先交付原型已演示的调色，不再以三个滤镜作为本阶段门槛。后续录制和直播必须保留调色结果。

## 7. 阶段 F：音频与混音器

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| F1 | 枚举音频设备并接入属性 | 区分输入设备和播放设备；先支持麦克风、桌面音频，辅助通道不凭空出现 |
| F2 | 读取真实麦克风声音 | 打开、持续采集、停止和断开均可验证；先单独验证清晰声音 |
| F3 | 读取桌面声音 | 选择播放设备并验证声音；无声不算异常，不能自动重复采集同一音频 |
| F4 | 接入每路电平与音量 | 用可控声音验证电平含义、音量变化及显示；显示真实数据 |
| F5 | 接入每路静音 | 静音后该路不进入混音，其他通道继续，取消静音后恢复 |
| F6 | 将两路声音混合 | 相对音量、静音和通道关系正确，避免重复声音，停止能结束等待 |
| F7 | 验证场景与设备关系 | 切换场景时全局音频与场景音频规则明确，复用来源不重复出声，设备变更失败能恢复 |

阶段验收：混音器控制实际声音，原型中的电平动画不作为实现或测试依据。

## 8. 阶段 G：音画同步录制

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| G1 | 保存可控合成画面 | 用固定或生成素材验证视频输出，时间正确，编辑边框不进入文件 |
| G2 | 生成完整可播放录像 | 设置保存位置，先支持 MP4，正常停止后文件完整，写入失败有提示 |
| G3 | 加入可控测试声音 | 检查音画对应与先后启动，不直接用两路时长相等代替同步验证 |
| G4 | 接入真实合成与混音 | 录制包含设备、布局、来源滤镜和混合声音，预览与输出一致 |
| G5 | 接通录制控制与时间显示 | 开始、停止、再次录制，录制中退出、无效路径和失败恢复正确 |
| G6 | 验证长期同步与稳定性 | 测开头、中间、结尾事件，区分固定偏差和漂移；先 10 分钟，再 30 分钟 |

阶段验收：完成多画面和混音录制。最小化窗口、关闭面板不影响输出；音画偏差有真实测试记录。

## 9. 阶段 H：直播与独立双输出

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| H1 | 保存并校验直播设置 | 地址、密钥和有效输出参数可配置；密钥遮蔽，取消不保存，运行中设置有明确限制 |
| H2 | 接通单次真实直播 | 本地服务端可以接收并播放合成画面和混合声音，启停和连接失败有明确结果 |
| H3 | 同时开启录制与直播 | 两个按钮独立，顺序不限，不重复启动共同采集；文件和直播内容分别验证 |
| H4 | 验证独立停止与重新开始 | 停直播不断录像，停录制不断直播；分别计时，再次启动一条输出不重置另一条 |
| H5 | 处理推流异常与恢复 | 超时或断线不拖住录制；恢复连接后行为明确；错误与恢复提示对应真实状态 |

阶段验收：覆盖仅录制、仅直播、同时运行和分别停止四类状态，不能以互斥模式替代。

## 10. 阶段 I：场景转场

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| I1 | 明确选择与转场操作 | 列表选择按原型切换当前场景；转场按钮先沿用原型切换到列表下一场景的行为；单场景不误操作 |
| I2 | 实现直接切换 | 来源与声音规则一致，录制和直播继续，输出内容切换正确 |
| I3 | 实现淡入淡出与时长 | 按用户时长过渡实际合成内容，连续点击受控；滑动与擦除先禁用，不用界面闪光冒充真实转场 |

阶段验收：切换与动画可以在录制文件和接收端看到，预览操作不重置输出时长。

## 11. 阶段 J：设置与内容恢复

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| J1 | 完善原型设置窗口 | 整理已接入的录制、直播、画布和帧率选项；确认保存、取消保留原值，无效参数有提示；未实现选项禁用 |
| J2 | 保存场景、来源及其属性 | 重新启动后布局、素材引用和滤镜正确恢复；找不到文件或设备时保留配置并提示 |
| J3 | 保存主题模式与停靠布局 | 重新打开后恢复，跟随系统保留的是模式；重置布局可恢复可用窗口，不恢复到屏幕外 |
| J4 | 验证配置异常与退出 | 无效或缺失配置可以回到可用默认状态；运行中退出受控结束，不保存假成功或假连接状态 |

阶段验收：原型中的有效设置成为真实可恢复配置；示例路径、设备、版本和模拟数据不直接进入成品。

## 12. 阶段 K：稳定性、统计与交付

| 步骤 | 本步目标 | 可审核的交付与验收 |
| --- | --- | --- |
| K1 | 接入真实输出统计 | REC/LIVE 时长、帧率、推流丢帧和发送码率含义明确；未接入指标用空状态；可继续按指标拆步 |
| K2 | 接入资源占用与诊断 | CPU、内存与错误信息有真实来源，提示不泄露密钥；不沿用原型随机数据 |
| K3 | 验证输出失败与积压 | 设备断开、写入失败、网络慢或断开时不无限增长内存；单路故障不误停正常输出；按定位问题分别修复 |
| K4 | 完成系统验收 | 连续启停 20 次、10/30 分钟录制、双输出、场景切换、最小化、主题与停靠操作有记录 |
| K5 | 完成交付说明 | 构建、测试、使用、原型对应情况、设备条件、实测指标、已知限制和第三方声明齐全 |

阶段验收：满足项目方案目标，自动测试与人工设备验收分开记录。只有全部目标达到后才宣称相应功能完成。

## 13. 后续扩展

以下内容先保留合适入口，按需要另拆小步骤：

- 更多画面滤镜：色度键、锐化、暗角等。
- 更多转场：滑动、擦除。
- 窗口采集、额外采集方式和摄像头自带音频。
- 辅助或应用音频、监听、音频滤镜、多音轨。
- 其他录像格式、输出模式、硬件编码设备与更高输出规格。

原型有选项但未接入时明确不可用，不在一个步骤内实现全部兼容性。

从新版 A1 主窗口外框开始。必要依赖、资源清理和时间处理随真实功能加入；原型决定产品交互，不能把其中的简化逻辑或模拟结果直接当作正式实现。
