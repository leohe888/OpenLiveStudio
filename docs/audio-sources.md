# 声音来源与混音

## 范围与操作

- “画面来源”和“声音来源”分别管理画面与声音。声音来源初始为空，添加后立即采集并显示输入电平；删除或隐藏摄像头画面不会控制麦克风。
- 可添加多个不同设备的麦克风或系统声音。同一端点 ID（含正在释放的旧会话）禁止重复添加，不按设备名称判断重复。每次添加明确选择设备，不绑定随系统设置变化的“默认设备”。
- 每个来源可重命名、删除、静音和调节 0–100% 音量，默认 100%。输入电平在音量、静音处理之前计算，静音时仍能检查设备是否收到声音。点击名称、调整音量或切换静音可选择相应通道。
- 来源属性允许修改名称，显示原设备。切换设备使用删除后重新添加。系统声音采集所选播放端点的整体声音，不支持按应用采集。
- 所有设置仅存在内存中。本阶段没有音频监听、自动增益、压缩器、限制器、音频滤镜、编码或录制启停功能。

## 采集与格式转换

Windows 使用 WASAPI 共享模式：麦克风从输入端点采集，系统声音通过播放端点的 loopback 采集。设备查询在独立查询线程执行，每个采集端点有自己的后台线程；不在 GUI 线程打开设备、读采样或执行重采样。

- 读取设备混音格式，支持 8/16/24/32 位 PCM、32/64 位浮点，以及可转换的多声道布局；24 位紧凑 PCM 展开后转换。
- 使用 FFmpeg `swresample` 转换为 48 kHz、双声道、交错浮点。单声道以单位增益送入左右两路，多声道按实际声道掩码进行转换。
- WASAPI 包时间戳采用 QPC 的 100 ns 值，转换为纳秒。时间戳无效时估计当前包时间；重采样输出使用连续采样计数分配时间戳。
- 每秒根据包时间戳、重采样延迟及已输出采样数估计设备时钟偏差，使用有界的重采样补偿。采样不连续或时间偏差超过 50 ms 时清空旧会话采样并重新建立时间基准。
- 系统声音在端点空闲时可能没有包，不据此误判断连；设备不可用、服务错误和格式错误进入故障状态。

WASAPI 接口依据：[loopback 采集](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)、[采样包、静音标志和时间戳](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)。

## 混音与缓冲

`AudioMixer` 在独立线程每 10 ms 输出 480 个双声道采样，即使来源为空也输出静音。采用 60 ms 输入抖动余量，按 QPC 时间线取各来源相应区间的采样；缺失部分补零，过期数据丢弃，不重复播放旧包。

各来源独立应用音量和静音后相加；计算限幅前的混音峰值，再将输出限制到 `[-1, 1]`。这属于简单硬限幅，过载可能失真，需通过来源音量调整。混音过载提示保留约一秒，电平有衰减显示。

- 采集队列上限为每来源 0.5 秒采样，超出时丢弃最旧数据并计数。
- 混音器只保留有界的未来采样和最新输出，按采样数生成连续时间戳。错过多个输出节拍时跳过落后的区间，并增加不连续计数，不进行无限追赶。
- 后续编码可使用 `setOutputEnabled()` / `takeOutput()` 的输出接口：默认关闭缓冲，启用后最多保留 100 块（1 秒），溢出计数由 `droppedOutputBlocks()` 获取。录制接入时必须处理溢出和不连续，不能忽略采样损失。
- GUI 每 40 ms 读取累计峰值和设备状态。不逐包投递 Qt 事件，不将 PCM 存入列表模型。最小化或停止处理 GUI 事件不会停止已启动的采集和混音线程。

音频包和混音时间戳已具备公共单调时间基准，但本阶段没有建立录制起点、编码 PTS、与合成画面的延迟对齐，也没有保证设备的物理端到端音画偏差；这些仍属于录制阶段。

## 故障与释放

单设备故障只清空该设备的采样，其他来源和混音继续工作；失败来源保留在列表中并显示具体错误。后台每秒尝试重新打开同一个端点 ID，不切到其他设备。恢复后重新初始化重采样和时间线，保留名称、音量及静音状态。

删除先将来源移出混音配置并请求采集停止，再后台关闭 WASAPI 客户端及释放 COM 资源。旧工作线程完全退出前禁止重开相同端点。正常操作不在 GUI 线程等待设备关闭；退出应用时等待采集、混音和查询线程完成。系统或驱动若阻塞打开/停止调用，进程内实现没有硬性退出超时保证。

## 验证

```powershell
ctest --test-dir build/recording-compositor-Debug --output-on-failure

# 在可访问真实设备的环境中，Qt 与 FFmpeg DLL 路径需已配置。
$env:OPENLIVE_AUDIO_HARDWARE = '1'
& ./build/recording-compositor-Debug/tst_audio.exe hardware hardwareFaultRecoveryAndIndependentSources -o audio-hardware.txt,txt
& ./build/recording-compositor-Debug/tst_mainwindow.exe canShowAndClose soundSourcesAndDialogs soundHardwarePreview -o audio-ui.txt,txt
```

- `audio.sources`：空列表、名称和设备唯一性、参数校验、通知期间删除、失败设备重试、混音音量/静音/限幅、输入电平、采样区间对齐、缺包补静音、旧会话清空、有界队列、无 GUI 事件时持续输出，以及三种采样率和六类 PCM 格式转换。
- 普通音频测试不要求打开真实设备，硬件项明确跳过。硬件验收检查麦克风和 loopback 的规范化采样、并行输入、资源停止及同端点故障恢复。`OPENLIVE_FORCE_AUDIO_DEVICE_FAILURE=<端点 ID>` 是测试故障注入入口，会实际关闭指定端点的采集会话；删除此环境变量后允许按正常重试路径恢复。
- UI 测试覆盖默认空白、添加、属性草稿取消/确认、删除、音量/静音绑定、通道不重叠、小窗口滚动、固定浅色配色及画面来源独立性；原生硬件 UI 项额外检查实际设备和最小化时混音输出持续增长。

故障注入不替代实际 USB 拔插验证。其他厂商/虚拟设备、多声道物理设备、长期时钟漂移、持续过载、内存趋势和录制音画同步仍需对应环境验收。
